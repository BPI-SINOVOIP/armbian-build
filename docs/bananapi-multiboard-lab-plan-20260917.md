# Banana Pi 跨板映像自動測試計畫

日期：2026-09-17。分支：`bpi-h618-recovery-network-20260915`。

## 目標與本輪界線

使用者要求先完成計畫並推送，再直接完成可離線實作的部分，之後才提供各板實測。目標是把目前 45 板別、444 套映像納入同一套可續作流程，避免重複燒錄、反覆人工追進度或為每片板重造工具。本輪不操作電源、UART 或儲存媒體，不重做 0845 已完成的十套基本循環。

軟體驗收與硬體驗收分開。離線完成不代表各板可開機，更不代表 444 套已通過；模擬結果不得匯入硬體通過數。先前 0845 的 RCU／LZMA 間歇失敗、服務失敗、缺測及共用 A1 引導差異保持原紀錄，不因新工具而洗掉。

## 設計與效率

1. 唯讀盤點既有映像及 SHA-256 旁檔，解析板別、OS、角色、架構與 SoC 家族。初次盤點不解壓 444 個巨檔；旁檔是宣告值，不當成實際內容核對。解析 shell 設定只能讀文字，不能 `source` 執行。
2. 排序固定為架構、OS、板別、映像角色。板型資格測試可另依 SoC 家族分組；同站一次一套，多個已配對站點可獨立並行，不讓同一 UART、電源或媒體被同時操作。
3. 每項工作綁定映像雜湊、站點與實體板號、引導配置摘要、測試版本。改任一條件就建立不同工作；不靠檔名或既有檔案存在判定通過。
4. SQLite 保存工作、逐階段結果、嘗試及事件；事務與站點鎖防重複領取。結果檔先持久保存再更新狀態。逾時或程序中斷保留未知／待恢復，不能自動重刷半寫媒體或假裝前一步完成。
5. 執行階段為前置核對、部署與回讀、客戶核心啟動、短測、返回救援。每階段有期限及獨立報告；短測失敗仍須回救援。故障返回失敗立即隔離站點，不自動處理下一套。
6. 沿用既有工具的媒體身分、完整回讀、原配套核心、UART 與嚴格 SSH 原則。不得為省時間跳過必要回讀；來源靜態核對才可依完整檔案身分及已核定雜湊快取。
7. 平台適配器與通用排程分離。適配器使用明確參數、固定程式摘要及有界子程序，不以 shell 拼接映像內容。報告綁定本次工作與嘗試，另記是否模擬，不接受模擬報告冒充實板。

## 站點與安全條件

每個站點必須明示實體板型、板號、可用映像板別、UART 穩定路徑、電源配對、測試媒體 CID／容量／控制器、救援配置摘要、可覆寫範圍及授權來源。沒有提供硬體時只建立停用範本；不從映像名稱推測 HW_ID、不把 M4 Zero EMAC 映像當成實體擴充板已驗證。

寫入僅由已核定平台適配器執行。備份核對及覆寫授權須綁定該片媒體，不能把 0845 授權套到其他板；SD 救援、boot0／boot1、RPMB、OTP／eFuse 不在一般映像批次授權內。無 eMMC 的板子需另核定 USB／網路測試區，不能假造 eMMC 路徑。

H618 的 SRAM 位址、FIT 偏移及 MMC 編號不能套到其他 SoC。現有 0845 腳本作為已實測原型參考；正式站點適配器須透過新契約及實板核定，不能把硬編原型改板名後就當通用支援。

## 接板後的最小流程

1. 提供板型／修訂、板號、DDR、供電、UART 接線及可覆寫媒體；一次確認電源與媒體配對。
2. 核定獨立救援路徑及大檔傳輸；先備份並核對、取得該媒體授權，再做一套完整循環及故障回救援。
3. 證據通過後啟用站點，依佇列測同板各 OS。保持來源原檔、失敗資料及唯一嘗試，不重做已符合相同條件的階段。
4. 先同系 H618，再按已取得硬體與適配成熟度擴至其他家族；不為等待某片板而阻塞其他獨立站點。
