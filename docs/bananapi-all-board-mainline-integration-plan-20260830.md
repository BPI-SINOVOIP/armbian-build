# Banana Pi 全系列主線整合計畫

日期：2026-08-30

工作分支：`bpi-integration-20260829`

官方同步基準：`origin/main`，提交 `eb6801d30cf7da1e93fac84e6e33d600981392b1`

全系列來源分支：`bananapi-family-optimization-20260826`，提交 `937e7e81a`

H618 現行整合提交：`609228ce815f600fafcdf7c9b2a158f0a1d0b28b`

## 一、目的

建立唯一的 Banana Pi 全系列 Armbian 整合分支。此分支必須同時具備：

1. 最新 Armbian `main` 建置框架與目錄配置。
2. 先前全系列 48 個板卡目標的設定、來源契約、建置工具、驗證守門、文件與證據登錄。
3. BPI-M4 Zero、BPI-M4 Berry 與新增 BPI-M4 Zero EMAC 目標的 H618 DDR、GPU、媒體、40-pin、無線及網路成果。
4. 可由後續人員或人工智慧從單一分支追蹤每塊板子的真實支援等級、限制與下一個驗證門檻。

`main` 只作為官方同步基準，不直接承載尚未完成審查的 Banana Pi 全系列改動。所有整合、建置與驗證先在 `bpi-integration-20260829` 進行。

## 二、稽核結論

目前的 `bpi-integration-20260829` 尚不是全系列整合分支：

- 相對 `origin/main` 的板級變更只直接涵蓋 `bananapim4berry`、`bananapim4zero` 與 `bananapim4zeroemac`。
- 全系列來源分支另有 369 個提交尚未納入。
- AI2N、AIM7、CM2、CM5 Pro、F2P、F2S、Forge1、M1 Super、M2C、M4、M4 Super、M6、R3 Mini、R4 Pro、SM10、W2、W3 等準備分支均未成為現行整合分支的祖先。
- 舊全系列分支盤點 48 個板卡目標；加入 `bananapim4zeroemac` 功能變體後，現行整合必須可追蹤 48 個產品板卡與 1 個獨立功能變體。

不修改工作樹的合併預檢顯示，完整合併會新增約 582 個檔案，並產生 26 個未合併檔案。衝突主要來自新版核心目錄搬移、建置框架更新、網路板設定及 H618 重複演進。

## 三、整合原則

### 3.1 保留歷史

- 使用一般合併提交納入 `bananapi-family-optimization-20260826`，保留每板、每階段與每個拒絕證據的提交關係。
- 不把 369 個提交壓成無法追溯的單一檔案快照。
- 合併提交本身只代表程式與證據整合完成，不自動代表實機、量產、授權或公開發布通過。

### 3.2 衝突判定

- Armbian 共用框架、函式介面、核心版本目錄及已上游更新的設定，以現行 `main` 為基準，再移植仍然必要的 Banana Pi 行為。
- Banana Pi 專用板型、來源契約、狀態登錄、驗證器與證據文件，保留全系列來源分支內容。
- H618 DDR、GPU、媒體、40-pin、Wi-Fi 與 EMAC 以目前整合分支已驗證版本為基準，補回全系列分支中未重複的工具與文件。
- 已由核心目錄重新命名取代的舊修補路徑，不保留失效副本；必要修補移至現行目錄並重新檢查套用條件。
- `.conf`、`.csc`、`.wip`、`.eos` 身分及 L0 至 L5 證據等級不得因合併而擅自提升。

### 3.3 安全與發布邊界

- 私有來源、簽章、PAC、預編譯 DRAM、專有韌體與不可確認再散布權的內容，維持原有拒絕或內部候選標記。
- 缺少實機證據的板卡最高維持 L2；L0 參考板不得因共用 SoC 或 donor DTS 而宣稱正式支援。
- `bananapir1` 維持停止支援與歷史封存身分。
- 整合後的分支不得直接視為 Armbian 官方已接受內容；可上游化的改動須另拆主題分支審查。

## 四、執行階段

### 階段 0：計畫先行

1. 單獨提交本計畫書。
2. 推送至 `origin/bpi-integration-20260829`。
3. 確認遠端提交與本機一致後，才開始程式整合。

### 階段 1：合併全系列歷史

1. 合併 `bananapi-family-optimization-20260826`，保留完整提交歷史。
2. 依第三節規則逐項處理 26 個衝突檔案。
3. 確認所有全系列分支提交均可由整合分支追溯。
4. 確認工作樹沒有衝突標記、未合併索引或意外刪除。

### 階段 2：主線相容修正

1. 將 Meson 修補移至現行 `meson64-7.2` 路徑並檢查內容。
2. 將仍必要的 Sunxi 修補移至現行核心目錄，淘汰已被上游取代的舊副本。
3. 校正 Filogic、MT7623、Rockchip、SpacemiT、Sunplus、Realtek、Renesas、VS680 與 Unisoc 的板型及來源設定。
4. 保留現行 H618 A1 DDR 與 EMAC 實作，避免舊版內容回退已驗證參數。
5. 檢查所有可執行工具的權限、直譯器、語法及相對路徑。

### 階段 3：資料與程式回歸

1. 執行全系列板卡盤點工具，確認 48 個產品板卡均存在且狀態欄位完整。
2. 對新增 EMAC 功能變體執行獨立測試，避免改變 48 板產品統計口徑。
3. 執行全系列資料一致性、板型設定、來源契約、候選驗證器與 H618 回歸測試。
4. 對所有 Shell 工具執行 `bash -n`，可用時執行 `shellcheck`。
5. 執行 Python 語法檢查與測試；不得依賴 GitHub Actions 作為品質證明。

### 階段 4：建置預檢

1. 逐板解析設定，確認板型、架構、核心分支、U-Boot、DTB 與來源函式可被現行框架辨識。
2. 依 SoC 家族執行不產生正式映像的來源及設定預檢。
3. 對已有 L2 證據的板卡核對既有映像、雜湊與唯讀內容證據是否仍可追溯，但不把舊映像誤寫為由新整合提交重建。
4. 因磁碟、硬體或私有來源不能重建的項目，保留明確阻擋原因，不以空白或跳過冒充成功。

### 階段 5：閉合與推送

1. 重新產生全系列盤點與整合狀態報告。
2. 記錄執行命令、通過數、失敗數、限制及仍需實機或授權協助的清單。
3. 提交合併後修正與驗證證據。
4. 推送至 `origin/bpi-integration-20260829`，核對本機與遠端提交一致。

## 五、驗收條件

整合作業只有在下列條件全部成立時，才能標示為「全系列程式整合完成」：

1. `bananapi-family-optimization-20260826` 為整合分支祖先，369 個提交不再缺失。
2. 48 個產品板卡均有板型定義、來源契約、證據等級及下一門檻；M4 Zero EMAC 另作功能變體追蹤。
3. 不存在 Git 衝突、衝突標記、失效核心路徑或被舊分支回退的 H618 修正。
4. 全系列本機確定性守門及 H618 專用回歸全部通過。
5. 所有未通過項目都有可重現錯誤與正確狀態，不得用文件宣稱掩蓋建置或實機缺口。
6. 遠端整合分支與本機最終提交一致。

本驗收只閉合來源、工具、設定、軟體證據與分支整合。逐板 L3 至 L5 實機驗證、授權核准、公開發布及 Armbian 官方合併仍依各板卡既有門檻個別執行。

## 六、中斷續跑點

- 計畫提交完成後，可從「階段 1」續跑。
- 合併提交存在但測試未完成時，可從衝突修正後的整合提交續跑，不重新製造另一組平行歷史。
- 每次續跑先確認目前分支、`git status`、本機與遠端提交，再執行尚未完成的階段。
- 不修改其他工作樹，不刪除未整合來源、原始證據、正式映像或使用者既有檔案。
