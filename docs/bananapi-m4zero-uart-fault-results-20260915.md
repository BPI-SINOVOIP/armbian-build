# 0845：UART 故障注入與救援復原

日期：2026-09-15。對應 [P4A 計劃](bananapi-m4zero-uart-ddr-plan-20260915.md)。

## 實測範圍

目標為使用者指定的 M4 Zero 0845。沿用卡上的 `build-009`、控制 ABI 1 與固定 smoke 封包；沒有寫入 SD／eMMC、操作槽 1 至 4、切換電源或進入 Linux。測試前核對既有 UART 實體路徑及占用狀態。

正常上載器仍拒絕壞封包。獨立工具 `tools/bpi_sram_uart_faults.py` 只接受下列固定來源，在私有複本產生故障，原檔保持不變：

- 長度：1,536 B。
- 封包 SHA-256：`8f98a2e2f612341b0d108f147cd6c9dcfbb957c4c0577c5d6e171c6e898bd062`。
- 本機來源：`output/evidence/bpi-sram-supervisor/build-009/spl2-smoke.sram`。

## 結果

每個案例先完成新的 nonce 交握及載入準備，只有確認同一 nonce 的 `loaded result=-1` 才發送執行命令，必須遭拒絕，最後再以新 nonce 交握。表中時間包含傳輸失敗處理、執行拒絕與重新交握，不是 DDR 效能。

| 案例 | 載入失敗、禁止執行及恢復交握 | 耗時 | 15 秒門檻 |
| --- | --- | --- | --- |
| 標頭 CRC 損壞 | 通過 | 2.128 秒 | 通過 |
| 負載 SHA-256 損壞 | 通過 | 2.184 秒 | 通過 |
| 宣告完整長度但提早結束 | 通過 | 2.127 秒 | 通過 |
| 傳送取消字元 | 通過 | 2.009 秒 | 通過 |
| 不傳送負載 | 通過 | 36.021 秒 | **未通過** |

故障測試後，正常工具重新傳送完整 smoke 並取得成功載入；沒有交接執行，隨後再次交握成功。最後維持供電、SPL1 等待命令，UART 已釋放。主機工具退出成功表示觀察到復原，**不等於時間門檻全部通過**。

## 發現與修正方向

舊版整包傳輸上限為 120 秒，並沿用 XMODEM 首包等待及重試流程；不能把逐字元期限當成完整接收期限。新版候選新增 10 秒無資料期限、成功接收後更新活動時間，並在外層及內層接收迴圈檢查整體期限，保留整包 120 秒上限。

初次只補迴圈檢查的候選，在完整 AArch64 執行模型中仍約 36 秒；因此不能以較小的函式替身測試通過宣告修正完成。後續候選補齊活動期限後，完整模型的空等測試才通過。**修正尚未部署到 0845，實板時間仍以本表為準。**

## 可重跑檢查

以下為離線測試，不操作 UART：

```bash
python3 -B -m unittest discover -s tests -p 'test_bpi_sram_uart*.py'
```

本階段新增故障注入測試 52 項，既有 UART 測試 35 項，合計 87 項通過。包含固定輸入驗證、五種故障、來源不變、控制字元與長度界限、nonce、執行守門、證據檔案獨占建立，以及故障後重新交握。
