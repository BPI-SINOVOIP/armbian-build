# BPI-CM6 rc3 完整測試與驗證手冊

**版次：2026-09-23｜Ubuntu 24.04 Noble／GNOME｜用途：候選驗證，不是發布合格證明。**

## 一頁快速順序

每張 SD、每次 eMMC 燒錄各建立一份獨立紀錄；按照下列順序執行，細節見後文相同測試 ID。任何必要項目未測，填 **BLOCKED**，不可填 PASS。

| 順序 | 測試 ID | 操作與關卡 |
| --- | --- | --- |
| 1 | CM6-001～002 | 拍載板版本、接線與散熱；確認可覆寫媒體；核對 ZIP 與解壓後 SHA。 |
| 2 | CM6-003 或 004 | SD 寫整碟 `.img`；eMMC 交給 Titan 匯入專用 ZIP。兩種檔案不可互換。 |
| 3 | CM6-005～007、013 | **上電前**開始 UART 接收；記錄乾淨首開藍牙，再做登入、身分、分區及 UUID 檢查。 |
| 4 | CM6-008～016 | 桌面、USB、eth0、eth1、Wi-Fi、藍牙及音訊；每個介面獨立留證。 |
| 5 | CM6-017～022 | 核對兩顆 NVMe 身分後先唯讀，再測明確准寫的既有檔案系統；GPU 像素比對、AI CPU 對照與實際後端追蹤。 |
| 6 | CM6-023～027 | 先測原 rc3 相機配置；另開候選批次測兩路 IMX415、雙路停止、立即重開與畫質。 |
| 7 | CM6-028～029 | 全程記溫度與降頻；散熱合格後才做 30 秒短壓測。 |
| 8 | CM6-030～033 | 暖重啟一次、正常關機後斷電至少五秒再開三次、關機與復原演練。 |
| 9 | CM6-034 | 保存原始資料、產生 SHA 清單、填 CSV 與缺陷報告；逐項簽核，候選與原版分開。 |

**立即停止條件：** 目標磁碟不明、載板接腳或開機選擇不明、供電不符、相機排線未斷電插拔，均停止相關操作。溫度達 90°C 停止新增負載；負載前須低於 75°C 且無降頻。這是本手冊的保守測試門檻，不是晶片額定值。

**本批已知未過：** 藍牙新卡首開軟體封鎖；Wi-Fi 接收丟棄計數增加；HDMI 青色畫面與 EDID 失敗；受測 AI 模型回退 CPU；雙相機停止逾時、畫質及 30 FPS 未驗收；SoC 曾達 92～94°C 並降頻。rc3 eMMC 整包仍須重新實測。測試不得掩蓋這些結果。

**結果碼：** PASS＝本項全部條件及證據齊全；FAIL＝已執行而不符條件；BLOCKED＝缺設備、工具、前置條件或證據；NA＝經審核確定該媒體／硬體不適用，須寫理由。空白不是結果。

## 1. 工作位置、證據規則與硬體準備

### CM6-001：建案與接線

本手冊只適用 BPI-CM6 的 `20260923-rc3`。K1 是 RISC-V 平台。不得將 F3、CM4、CM5 或 BPI-M6 的接腳、工具或映像套用到 CM6。既有 Armbian 原始格式與本官方格式相容候選是不同流程。

pi-88 的交付根目錄如下。離線測試人員應取得兩個媒體目錄及共同的 `驗證文件`，保持相對位置。

```text
/media/pi/SMCI/bpi/f3-cm6-vendor-20260923-rc3/output/
  bpi-cm6-sd/       ← SD ZIP、manifest.json、verification.json、SHA
  bpi-cm6-emmc/     ← Titan ZIP、manifest.json、verification.json、SHA
  驗證文件/        ← 本手冊 MD/PDF、CSV、驗證工具、SHA256SUMS
```

準備下列設備，記入主機案件的 `host/CM6-001-hardware.md`，拍攝 `photos/CM6-001-carrier.jpg`、`photos/CM6-001-wiring.jpg`。照片不得包含網路密碼、帳密標籤或敏感畫面。

- CM6 模組序號／版本、RAM 容量、eMMC 容量；載板完整型號與 PCB revision；實物上的開機開關位置照片。參考原理圖是 **V00**，不代表目前待測載板已確認為 V00。
- 符合該載板官方規格的電源、額定電壓／電流、實測供電方式；散熱片、導熱材料、風扇與室溫。先確認供電，不猜電源口規格。
- 可覆寫且容量足夠的 SD、讀卡器、USB 資料線、Linux 測試主機；Titan 可用 Windows 或 Linux，記錄 OS、實際版本及安裝檔 SHA。
- 3.3 V TTL UART，115200 baud、8 資料位、無同位、1 停止位、無流控。**板 TX 接轉接器 RX、板 RX 接 TX、共地；不接 VCC，也不接 RS-232 電平。** 接腳依對應 revision 原理圖核對。
- 已知良好 HDMI 螢幕與線、擷取器（若有）、USB 鍵鼠、既有檔案系統的測試隨身碟；GbE 交換器與兩條線、隔離測試 AP、可配對的藍牙測試設備、喇叭／耳機與麥克風。
- 128 GB 與 256 GB NVMe 的型號、序號及准許寫入範圍；兩顆相容 IMX415、正確排線／轉接板與均勻光源、解析度／色彩測試圖。**相機排線只在完全斷電時插拔。**

本機歷史接法為 UART `/dev/ttyUSB0`、HID `/dev/ttyUSB1`、電源 `bpi-pw-2`，只作定位線索；每次須按 USB 身分重新核對，不能靠枚舉號自動操作。擷取主機的 `/dev/video0` 與 CM6 的 `/dev/video0` 是不同設備；後者曾是編解碼器，不能直接當 CSI 相機。

**主機工具檢查：** Bash、Python 3、pyserial、unzip、sha256sum、lsblk、Etcher、Titan；收集與後端工具的缺失按個別測項列 BLOCKED，不先全面升級候選系統。工具包含 GPU 測試、AI 固定模型及相機配套；應從本次交付取得，不任意抓浮動版本。

```bash
python3 -c 'import serial; print(serial.VERSION)'
command -v python3 unzip sha256sum lsblk
```

**PASS：** 型號、revision、容量、接腳、供電與准寫範圍皆明確且有照片。缺一必要資訊則相關測項 BLOCKED；不得用推測補欄位。

### 共用記錄方法

【主機】在一般使用者終端機建立案件；以下變數需在各自的終端機重新設定。`CASE` 用匿名板號，勿用帳號或密碼。SD／eMMC 及每次重燒各用新案件後綴；原版與相機候選用本手冊不同測項子目錄分開，CSV 備註明確標記配置。

```bash
umask 077
read -r -p '案件代號（例如 CM6-A01-sd-rc3-R01）：' CASE
[[ "$CASE" =~ ^[A-Za-z0-9_-]+$ ]] || exit 1
E="$HOME/cm6-evidence/$CASE"
mkdir -m 700 -p "$HOME/cm6-evidence"
mkdir -m 700 "$E" || exit 1
mkdir "$E/host" "$E/board" "$E/photos" "$E/defects"
DOC='/media/pi/SMCI/bpi/f3-cm6-vendor-20260923-rc3/output/驗證文件'
cp "$DOC/BPI-CM6-rc3-測試結果表-20260923.csv" "$E/results.csv"
```

離開 pi-88 時將 `DOC` 改成下載後的共同文件目錄。以安全管道取得首次登入資料，**本手冊、命令列、CSV、截圖、UART 與日誌均不得寫入密碼或金鑰**。不要執行 `set -x`、`nmcli --show-secrets`、列印環境變數，或複製 NetworkManager 連線設定／私鑰。登入及輸入密碼時不開終端錄影；必要時先結束 UART 接收並記錄停錄時段。

【板端】完成帳號建立後，把 `驗證工具` 整個目錄以現場核實的 SSH 或已知 USB 媒體傳到 `$HOME/cm6-tools`。不提供內嵌帳密的遠端命令。輸入相同 `CASE`，建立獨立板端目錄：

```bash
umask 077
read -r -p '案件代號：' CASE
[[ "$CASE" =~ ^[A-Za-z0-9_-]+$ ]] || exit 1
E="$HOME/cm6-evidence/$CASE/board"
mkdir -m 700 -p "$HOME/cm6-evidence/$CASE"
mkdir -m 700 "$E" || exit 1
T="$HOME/cm6-tools"
(cd "$T" && sha256sum -c SHA256SUMS) > "$E/tools-sha256.txt" 2>&1
```

板端一般使用者先執行 `export PATH="/usr/sbin:$PATH"`，確保找到診斷命令。每次測試用新證據檔；命令若失敗保留原檔，重測命名加 `-R02`，不得覆蓋。下文 `|& tee` 需在 Bash 執行；**先 `set -o pipefail`**，以免 `tee` 掩蓋失敗。每組命令把真實退出碼、開始／結束時間、人工觀察寫入該測項記錄。`sudo` 驗證先在未錄製的終端完成。

共用收集器：

```bash
sudo bash "$T/collect_cm6_rc3_validation.sh" --output "$E/baseline"
```

以 `sudo` 執行的收集器／相機工具會建立 root 所有的私有目錄。每次完成後，先確認 `$E` 是本案件的 `board` 證據目錄，再只調整這個目錄的所有權，讓一般使用者可讀及傳檔；不可對 `/`、`/root` 或整個家目錄執行：

```bash
realpath "$E"
test "$E" = "$HOME/cm6-evidence/$CASE/board" || exit 1
test -d "$E" && test ! -L "$E" || exit 1
sudo chown -R --no-dereference -- "$(id -u):$(id -g)" "$E"
```

每次重開／重新登入後，shell 變數不會保留。**不要重新建立已存在的案件**，使用以下捷徑重設路徑：

```bash
read -r -p '既有案件代號：' CASE
[[ "$CASE" =~ ^[A-Za-z0-9_-]+$ ]] || exit 1
E="$HOME/cm6-evidence/$CASE/board"
T="$HOME/cm6-tools"
CAMROOT="$HOME/cm6-camera-$CASE"
ORIG="$E/CM6-024-extlinux.original.conf"
export PATH="/usr/sbin:$PATH"
test -d "$E" || exit 1
```

它只收集，不啟用裝置，也不把退出碼零當硬體 PASS。每個命令有獨立 stdout／stderr 與 `command-status.tsv`；缺工具或逾時有明確狀態。必須檢查表內失敗，不能只看收集器退出成功。

## 2. 成品、容量與完整性

### CM6-002：核對檔案

所有大小均為精確 **bytes**，不是磁碟廠商標称 GB。兩種媒體 `minimum_media_bytes` 都是 **6,716,129,280**；實際媒體必須不小於此值，建議準備 16 GB 以上。主機應保留至少 20 GB 空間，證據照片／錄影另計。

**SD 壓縮檔**

```text
Armbian_Noble_bpi-cm6_gnome_vendor-sd_20260923-rc3.img.zip
大小：1713117447
SHA-256：228cef7811e763cbf0b8f0d57d55ba78f79f87f2f3bf5e7f59d5d53bd94c78a7
```

**SD 解壓後整碟映像**

```text
Armbian_Noble_bpi-cm6_gnome_vendor-sd_20260923-rc3.img
大小：6716129280
SHA-256：562cd7820b788df1a35e4763a23d585262684015c0fbb2921fc1fa23c0608766
```

**Titan eMMC 套件**

```text
Armbian_Noble_bpi-cm6_gnome_titan-emmc_20260923-rc3.zip
大小：1713113819
SHA-256：06e02aa4bfb309535e7858add46d20745f5fbf65f94ccfd21e4acf974e2d55a3
```

SD ZIP 僅含一份整碟 GPT `.img`。Titan ZIP 是十個分區／載荷及設定成員，含 `fastboot.yaml` 與 `partition_universal.json`；**它不是整碟映像，不能交給 Etcher／dd，也不能改副檔名互換**。`bootinfo_sd.bin` 等名稱屬固定官方協定配置，不自行換成看似更合適的成員。

【主機】設定交付根目錄後核對；下面只讀檔案，不會燒錄：

```bash
OUT='/media/pi/SMCI/bpi/f3-cm6-vendor-20260923-rc3/output'
SD='Armbian_Noble_bpi-cm6_gnome_vendor-sd_20260923-rc3.img'
EM='Armbian_Noble_bpi-cm6_gnome_titan-emmc_20260923-rc3.zip'
set -o pipefail
{
  stat -c '%n %s' "$OUT/bpi-cm6-sd/$SD.zip" "$OUT/bpi-cm6-emmc/$EM"
  (cd "$OUT/bpi-cm6-sd" && sha256sum -c "$SD.zip.sha256")
  (cd "$OUT/bpi-cm6-emmc" && sha256sum -c "$EM.sha256")
  unzip -t "$OUT/bpi-cm6-sd/$SD.zip"
  unzip -t "$OUT/bpi-cm6-emmc/$EM"
} |& tee "$E/host/CM6-002-archives.txt"
mkdir "$E/host/sd-unpacked" || exit 1
unzip -n "$OUT/bpi-cm6-sd/$SD.zip" -d "$E/host/sd-unpacked"
stat -c '%n %s' "$E/host/sd-unpacked/$SD"
sha256sum "$E/host/sd-unpacked/$SD" | tee "$E/host/CM6-002-image.sha256"
```

也可在 Windows 用 `Get-FileHash -Algorithm SHA256 -LiteralPath <實際 ZIP 路徑>`，大小用 `(Get-Item -LiteralPath <實際路徑>).Length`。尖括號不是可直接貼上的參數，必須換成實際路徑。Titan 可自行解包；人工查看時解至新目錄，不重壓或修改套件。

**PASS：** 上述大小、三個 SHA 與本頁固定值完全相符，ZIP 檢查無錯。每一行均須核對；某行成功不代表整組成功。**FAIL：** 任一不符，停止燒錄並重新取得成品。證據：`host/CM6-002-archives.txt`、`host/CM6-002-image.sha256`，另保存兩個 manifest 與 verification 到各自的 `host/sd-metadata/`、`host/emmc-metadata/`，不可互相覆蓋。

## 3. 燒錄：只執行本案件選定的一種媒體

### CM6-003：SD 整碟燒錄

**破壞性警告：燒錄會覆寫選定磁碟的分區及全部資料。不得選主機系統碟、備份碟、未知 USB 碟或單一分區。** 本手冊刻意不提供自動找卡後執行 `dd` 的腳本。

1. SD 插入前及插入後，分別執行 `lsblk -b -o NAME,PATH,TRAN,MODEL,SERIAL,SIZE,TYPE,MOUNTPOINTS`，保存為 `host/CM6-003-before.txt`、`host/CM6-003-after.txt`。按新增裝置、卡片實物／容量／序號共同核對；只看 `/dev/sdX` 名稱不夠。
2. 確認可覆寫授權及資料備份；卸載**已辨識目標**的掛載分區。不可執行萬用字元卸載或自動取第一顆磁碟。
3. 開啟 Etcher，記錄版本。在 `Flash from file` 選 CM6-002 已核對的 `.img`；在 `Select target` 核對磁碟容量與實物；再按 `Flash!`。讓工具完成寫入後驗證，保存 `photos/CM6-003-flash.png`。
4. 彈出卡片，再插回讀卡器但不要開機；人工指定剛才同一張卡的**整碟**路徑，唯讀回讀前 6,716,129,280 bytes。此處不會寫磁碟：

```bash
read -r -p '已核對的 SD 整碟路徑：' CARD
lsblk -b -o NAME,PATH,MODEL,SERIAL,SIZE,TYPE,MOUNTPOINTS "$CARD"
sudo blockdev --getsize64 "$CARD"
# 只有容量與實物確認一致才繼續；以 pipefail 檢查讀取是否成功。
set -o pipefail
sudo head -c 6716129280 "$CARD" | sha256sum \
  | tee "$E/host/CM6-003-readback.sha256"
```

**PASS：** Etcher 寫入／驗證皆成功，回讀 SHA 等於 SD 原始映像 SHA。開機後會擴容及寫檔，不得再要求整卡雜湊仍等於原始檔。**FAIL：** 回讀短讀、I/O 錯誤或 SHA 不同。證據含目標識別與 `host/CM6-003-readback.sha256`。eMMC 案件此項填 NA。

### CM6-004：Titan eMMC 燒錄

**破壞性警告：Titan 會改寫 eMMC；本候選並未在包內硬鎖目標媒體。** 先正常關機、斷電，拔除 SD、NVMe 及其他可寫入儲存裝置。核對載板 revision 的 eMMC 開機選擇；不確定則 BLOCKED，不猜 DIP／跳線、不選 NOR／NAND／MTD 設定。

1. 從[CM6 官方入門頁](https://docs.banana-pi.org/en/BPI-CM6/GettingStarted_BPI-CM6)進入 Titan 工具下載。2026-09-16 留存入口是 `1.0.35-beta`，**尚無 rc3 的 Titan 相容版本已驗證清單**。記錄工具實際版本、安裝檔名／SHA、主機 OS、驅動版本於 `host/CM6-004-titan-version.txt`；不只填「最新版」。
2. 主機僅連一片待測 CM6；用可傳資料的 USB 線直連載板指定下載口。按實物／官方文件核對 `DOWNLOAD/FEL` 按鍵：斷電時按住再接電，或按住後觸發重置，再依官方流程放開。不要把電源口當成下載口，不套用 F3 的按鍵圖。
3. Titan 單機模式確認被識別的板子，保存 VID:PID／序號及 `photos/CM6-004-detected.png`。無識別先查線、供電、下載模式與驅動；不可猜測改 EEPROM。
4. 匯入 **`Armbian_Noble_bpi-cm6_gnome_titan-emmc_20260923-rc3.zip`**，等待解包及配置載入。再次確認目標後開始燒錄；保存**從連線到結束**的原始日誌為 `host/CM6-004-titan.log`，完成畫面為 `photos/CM6-004-result.png`。
5. 完成後完全斷電，退出下載狀態，保持 SD、NVMe 已移除，再按下一節從上電前錄 UART；確認 eMMC 獨立開機與本批 UUID。不要以「工具成功」代替啟動驗證。

**PASS：** Titan 全流程成功＋正確 rc3 eMMC 身分獨立冷開成功。**FAIL：** 匯入、分區匹配、傳輸或啟動任一步錯誤。`Code 20014` 需保留原始日誌，不改 ZIP、不刪元件、不自行寫 `boot0`。SD 案件填 NA。rc2 使用者曾回報 Titan 燒錄啟動成功，**不能代替本批 rc3 結果**。

## 4. 上電、首開與系統基線

### CM6-005：上電前 UART、冷開與首次設定

【主機】只接已核對 UART，確認沒有另一個終端程式占用；HID 串口不得使用。接收器只讀、不會送登入資料。pyserial 缺少則先在測試主機補足，無 UART 證據的本項列 BLOCKED。

```bash
read -r -p '已核對的 UART 路徑：' UART
python3 "$DOC/驗證工具/cm6_rc3_uart_capture.py" \
  --port "$UART" --output "$E/host/CM6-005-first-power.uart.bin" \
  |& tee "$E/host/CM6-005-capture.txt"
```

看到「接收已就緒」才上電，在另一份 `host/CM6-005-timeline.txt` 記錄 UTC 上電時間、電源指示、首個 UART 字元、核心啟動、登入提示及可登入時間。最多等五分鐘；無進度或 panic 記 FAIL，先留證再復原。第一次可能有檔案系統初始化與設定，不中途拔電。

```bash
export PATH="/usr/sbin:$PATH"
read -r -p '主機測試 LAN IPv4：' PEER
D="$E/$PREFIX"
mkdir "$D" || exit 1
ip -s -j link show dev "$IFACE" > "$D/before.json"
ip route get "$PEER" oif "$IFACE" > "$D/route.txt"
ping -I "$IFACE" -c 10 -W 2 "$PEER" > "$D/ping.txt" 2>&1
run_curl() {
  local STEP=$1 RC
  shift
  curl --fail --max-time 60 --interface "$IFACE" "$@" 2> "$D/$STEP.stderr"
  RC=$?
  printf '%s\n' "$RC" > "$D/$STEP.exit"
  return "$RC"
}
run_curl expected "http://$PEER:8000/sha256" -o "$D/expected.sha256" || exit 1
run_curl download "http://$PEER:8000/payload" -o "$D/download.bin" || exit 1
stat -c '%s' "$D/download.bin" > "$D/download.bytes"
test "$(cat "$D/download.bytes")" = 8388608 || exit 1
sha256sum "$D/download.bin" | cut -d ' ' -f 1 > "$D/download.sha256"
run_curl upload --data-binary "@$D/download.bin" \
  "http://$PEER:8000/upload" -o "$D/upload.sha256" || exit 1
cmp "$D/expected.sha256" "$D/download.sha256"
printf 'download_compare_rc=%s\n' "$?" | tee "$D/compare.txt"
cmp "$D/expected.sha256" "$D/upload.sha256"
printf 'upload_compare_rc=%s\n' "$?" | tee -a "$D/compare.txt"
ip -s -j link show dev "$IFACE" > "$D/after.json"
{ nmcli -f GENERAL,IP4 device show "$IFACE";
  sudo ethtool "$IFACE"; sudo dmesg --color=never;
} > "$D/link-and-kernel.txt" 2>&1
```

每條 curl 都應退出 0，下載檔必須 **8,388,608 bytes**；缺任一輸出先停，不因兩個空檔 cmp 相同就通過。核對 `before.json`／`after.json` 的 `stats64`（或 `stats`）收送 bytes 確實增加、errors／dropped 差值；資料雜湊須同時符合對端固定資料 SHA，見工具啟動輸出。固定資料 SHA-256 為 `7d212b9c884f5c77896de960ae17cc341cda43b14d6a971f34ca29ebd4badf7f`，三份雜湊檔均須逐字等於此值；對端可讀不代表測試路徑正確，仍須檢查介面收送計數。

**有線 PASS：** 指定埠 Link detected yes、1000 Mb/s／Full、DHCP、10 次 ping 零丟包、雙向 SHA 相同、收送錯誤及丟棄零增；拔插後可恢復。已知 100 Mbps 對端不作 GbE PASS，先更換或列 BLOCKED。

### CM6-017／018：128 GB／256 GB 唯讀

**不得把磁碟序號當固定名稱。** 先以 `lsblk`／`nvme list` 核對型號、序號、容量、所有分區與掛載點，拍實物標籤（遮掉不宜外傳資訊）。既有證據是 Kingston 128,035,676,160 bytes 與 Fanxiang 256,060,514,304 bytes，不表示其他容量已測。

【板端】分兩次人工填 `DEV`，128 GB 使用 `CM6-017`，256 GB 使用 `CM6-018`：

```bash

read -r -p '本次測項 ID（CM6-017 或 CM6-018）：' ID
D="$E/$ID"

{ lsblk -b -o NAME,PATH,MODEL,SERIAL,SIZE,TYPE,FSTYPE,MOUNTPOINTS;
  sudo nvme list; sudo nvme id-ctrl "$DEV";
} > "$D/identity.txt" 2>&1
sudo nvme smart-log "$DEV" -o json > "$D/smart-before.json"
sudo nvme error-log "$DEV" -o json > "$D/errors-before.json"
```

人工核對這是預定 NVMe **整碟**、容量足夠、非系統／活躍資料碟後才繼續。若有其他程序寫入，先由資料管理者停止，否則重讀 SHA 變化無法判讀，列 BLOCKED。以下 `dd` 只有 `if=` 指向磁碟，**不得加 `of=/dev/...`**。

```bash
BYTES=$(sudo blockdev --getsize64 "$DEV") || exit 1
[[ "$BYTES" =~ ^[0-9]+$ ]] && (( BYTES >= 100663296 )) || exit 1
MIB=$((BYTES / 1048576))
set -o pipefail
for POS in 0 $((MIB / 2)) $((MIB - 32)); do
  for ROUND in 1 2; do
    sudo dd if="$DEV" bs=1M skip="$POS" count=32 \
      iflag=direct,fullblock status=none \
      | sha256sum > "$D/read-${POS}-${ROUND}.sha256" || exit 1
  done
  cmp "$D/read-${POS}-1.sha256" "$D/read-${POS}-2.sha256" || exit 1
done
sudo nvme smart-log "$DEV" -o json > "$D/smart-after.json"
sudo nvme error-log "$DEV" -o json > "$D/errors-after.json"
sudo dmesg --color=never > "$D/kernel-after.txt"
```

**PASS：** 三處各 32 MiB 兩讀相同、無短讀／timeout／I/O 錯誤，SMART `critical_warning=0`，`media_errors`／`num_err_log_entries` 不增加。既有非零項另立缺陷，不用前後相同掩蓋健康異常；`unsafe_shutdowns` 需記前後差值。證據為各自 `$ID/` 全目錄。這不是完整容量讀測，也不是速度基準。

### CM6-019：256 GB 既有檔案系統暫存檔讀寫

歷史 128 GB 沒有既有檔案系統，只有唯讀證據；**不得為湊齊項目格式化它**。本項限已確認准寫的 256 GB 既有 ext4，沒有這樣的分區就 BLOCKED。若測其他磁碟，另建測項及授權記錄，不借用本項 PASS。

1. 在 `CM6-019-authorization.md` 記錄實物序號、分區、所有者、准寫暫存範圍與容量；不得含登入資料。
2. 人工設定分區，先 `findmnt --source "$PART"` 確認未掛載；`sudo tune2fs -l "$PART"` 應顯示乾淨 ext4。不得測系統 root／boot、未知／髒檔案系統，不自動修復。

```bash
read -r -p '已核對且准寫的 256 GB NVMe ext4 分區：' PART

sudo tune2fs -l "$PART" > "$E/CM6-019-ext4-before.txt"
# 僅在未掛載、狀態乾淨、身分正確並獲准後執行以下步驟。
M=$(mktemp -d /tmp/cm6-nvme.XXXXXXXX) || exit 1
sudo mount -t ext4 -o rw,nosuid,nodev,noexec "$PART" "$M" || exit 1
findmnt -T "$M" | tee "$E/CM6-019-mount.txt"
df -B1 "$M"
```

確認可用空間至少 512 MiB，板端證據目錄亦至少 300 MiB；只寫新建隨機目錄。保留前後 SMART（命令同 CM6-018，輸出改 `CM6-019-smart-before.json`／`CM6-019-smart-after.json`）。

```bash

dd if=/dev/urandom of="$E/CM6-019-reference.bin" \
  bs=1M count=256 conv=fsync status=none || exit 1
test "$(stat -c %s "$E/CM6-019-reference.bin")" = 268435456 || exit 1
sha256sum "$E/CM6-019-reference.bin" | cut -d ' ' -f 1 \
  > "$E/CM6-019-expected.sha256"

  bs=1M conv=fsync status=none || exit 1

test "$(cat "$E/CM6-019-written.bytes")" = 268435456 || exit 1
set -o pipefail

  iflag=direct,fullblock status=none | sha256sum | cut -d ' ' -f 1 \
  > "$E/CM6-019-actual.sha256"
READ_RC=$?
printf 'read_rc=%s\n' "$READ_RC" > "$E/CM6-019-result.txt"
cmp "$E/CM6-019-expected.sha256" "$E/CM6-019-actual.sha256"
printf 'compare_rc=%s\n' "$?" >> "$E/CM6-019-result.txt"

findmnt --source "$PART" > "$E/CM6-019-cleanup.txt"
```

最後 `findmnt` 應無輸出、退出 1 表示已無該掛載；此處不是測試失敗。若中途失敗先保留證據，再只清理本輪記錄的 `NV_TMP`，不要盲目重跑。**PASS：** 參考檔與 NVMe 寫後檔皆精確 268,435,456 bytes，`read_rc=0`、`compare_rc=0`，256 MiB 寫入／fsync／直接回讀 SHA 相符、SMART 錯誤不增、清理與卸載完成。這不是整碟耐久或斷電保護驗收。

## 9. 溫度、降頻與短壓測

### CM6-028：空載與各負載的溫度記錄

散熱裝好後，在桌面空載五分鐘；每秒記錄所有 thermal zone、CPU 上限／目前頻率及 cooling 狀態。以下在獨立終端執行；`LABEL` 每輪改成 `idle`、`gpu`、`ai-v2`、`camera-dual` 等，不能覆蓋。

```bash
LABEL=idle
set -o pipefail
while :; do
  date -u --iso-8601=seconds
  for Z in /sys/class/thermal/thermal_zone*; do
    test -d "$Z" || continue
    printf '%s ' "$Z"; cat "$Z/type" "$Z/temp"
  done
  for C in /sys/class/thermal/cooling_device*; do
    test -d "$C" || continue
    printf '%s ' "$C"; cat "$C/type" "$C/cur_state"
  done
  for P in /sys/devices/system/cpu/cpufreq/policy*; do
    test -d "$P" || continue
    printf '%s ' "$P"
    cat "$P/cpuinfo_max_freq" "$P/scaling_max_freq" "$P/scaling_cur_freq"
  done
  sleep 1
done | tee "$E/CM6-028-$LABEL.txt"
```

五分鐘後 Ctrl+C 結束空載記錄；負載前另啟新記錄，測試結束再 Ctrl+C。溫度原值通常是毫攝氏，`94000` 即 94°C。以 `scaling_max_freq` 降低或 cooling state 增加作降頻證據，**不能把空載 `scaling_cur_freq` 較低直接叫過熱降頻**。

**PASS：** 本次要求的空載／各負載全程感測有效、未達 90°C、無熱警告與降頻，上限符合此配置預期。**FAIL：** 實測過熱／降頻；缺感測器或散熱條件不明 BLOCKED。原本記錄最高 92～94°C、cooling state 2、上限由 1,600,000 降為 1,228,800 kHz，維持 FAIL；115°C 核心臨界門檻不能當允許持續壓測的依據。

### CM6-029：30 秒、兩個 worker 的 CPU 短測

rc3 沒有 `stress-ng`，不為此升級系統。附帶工具只跑受控 CPU 負載，拒絕不安全輸出路徑，不寫儲存裝置。工具會先檢查溫度低於 75°C、可讀散熱與頻率資訊、無降頻，未滿足則 **不啟動 worker**。

```bash
python3 "$T/cm6_rc3_short_stress.py" \
  --output "$E/CM6-029-short-stress" --seconds 30 --workers 2 \
  > "$E/CM6-029-console.txt" 2>&1
printf 'rc=%s\n' "$?" > "$E/CM6-029-exit.txt"
```

每 0.5 秒記溫度、頻率／cooling；達 90°C、出現降頻、worker 異常或取樣失敗即停。檢查 `summary.json`、`temperature.csv` 與所有 worker 退出碼／清理結果。

**PASS：** 完整 30 秒、退出 0、無熱／頻率／程序異常且全部子程序回收。退出 1 FAIL；2 BLOCKED。此項只代表兩個 worker 的 30 秒短測，不等於全核心、GPU＋CPU 混合、長時間穩定或量產燒機通過。

## 10. 重開、關機與復原

完成相機候選後先確認原 extlinux 已恢復。下列原版回歸不能在不明候選上做。把板端證據同步到主機後，再進行電源操作。

### CM6-030：暖重啟一次

1. 【板端】保存 `cat /proc/sys/kernel/random/boot_id` 為 `CM6-030-before-boot-id.txt`；完成 `sync`。
2. 【主機】按 CM6-005 先開新 UART 檔 `host/CM6-030-reboot.uart.bin`。
3. 【板端】執行 `sudo systemctl reboot`；主機不得切斷電源。
4. 五分鐘內恢復登入後，先用第 1 章捷徑重設板端路徑，保存新的 boot_id 至 `CM6-030-after-boot-id.txt`，重跑身分／掛載核對及收集器至 `CM6-030-after/`；各埠 ping、藍牙 `Powered` 與桌面檢查另存 `CM6-030-regression.txt`。

**PASS：** boot_id 改變、來源媒體與 UUID 正確、原版 DTB 恢復、無 panic／新增失敗單元，重開後的已驗基本功能仍可用。藍牙先前解除後恢復，只是持久狀態結果，不改寫 CM6-013 的首開 FAIL。

### CM6-031：三次真正冷開機

逐次使用 `01`、`02`、`03`，**不要以 reboot 代替斷電**：

1. 保存當前 boot_id、正常 `sync` 後 `sudo systemctl poweroff`。UART 出現 `Power down` 才切斷實際主供電，確認電源指示熄滅；排除 USB／UART VCC 反向供電。
2. 記錄斷電與上電 UTC 時間，斷電至少五秒。主機先開 `host/CM6-031-cold-01.uart.bin` 接收才上電；另外兩次只改序號。
3. 每次五分鐘內可登入後，先用第 1 章捷徑重設板端路徑，再保存 `CM6-031-cold-01-state.txt`：boot_id、身分、UUID、`ip -br address`、兩埠 `ethtool`、指定介面 ping、`rfkill list`、`bluetoothctl show`、`systemctl --failed`；桌面照片另存相同序號。
4. 三次均核對原版 `sensor2` disabled，確認候選未偷偷留在預設開機設定；不要為此要求第二路原版通過。

**PASS：** 三次都有可核對的斷電間隔、完整 UART 與狀態，全部正常啟動且原版行為可重現。任何一輪 FAIL，整項 FAIL；缺供電證據則 BLOCKED。已知藍牙首開缺陷仍獨立保留。

### CM6-032：正常關機

【主機】先開 `host/CM6-032-poweroff.uart.bin`。板端保存 `findmnt`、`systemctl --failed`，確認測試程序結束、測試檔清理與 NVMe 卸載；執行 `sync`、`sudo systemctl poweroff`。

記錄命令到 UART `Power down` 的秒數、電源指示與裝置狀態至 `host/CM6-032-observation.txt`。**PASS：** 兩分鐘內完成受控關機、無檔案系統／卸載錯誤且不自行重啟；最後才關主供電。若無 `Power down`，先留 UART、等候並列 FAIL，不把直接拔電寫成正常關機成功。

### CM6-033：復原與回退演練

不故意破壞分區、模擬掉電寫入或改壞 DTB。用可開機復原 SD 與已保存設定，驗證實際可回到原版：

- **SD 候選能登入：** 依 CM6-024 還原 extlinux；暖重啟後核對原 DTB、UUID、網路，保存 `CM6-033-restored-state.txt` 與 `host/CM6-033-recovery.uart.bin`。
- **SD 候選不能登入：** 保存失敗 UART、正常可行時先關機；確需強制斷電則記事故時間。把該卡接讀卡器，按序號及 SD bootfs UUID 人工辨識第 5 分區。先以 ext4 `ro,noload` 唯讀掛載（避免 journal replay 寫入）查看 `extlinux/extlinux.conf` 並與主機備份比較；确认只有本次已知變更後，卸載並將**同一已辨識分區**掛成可寫，還原備份，`sync`、卸載再試。無法確認身分則 BLOCKED，不修其他分區。
- **eMMC 不能啟動：** 先拔除無關媒體，用已驗 SD 依實際載板開機設定啟動，保存 `lsblk`、eMMC 型號／容量與 UUID；只讀檢查 eMMC bootfs。確認可回復且有原備份才處理本次設定差異。若需重燒，回 CM6-004，重新確認 eMMC 可覆寫並留完整 Titan 日誌，不能自動格式化。

板端／主機針對已辨識的 bootfs 分區可依下列模板操作。**BOOTPART 必須由人工輸入與核對，不自動找磁碟；BACKUP 必須是該媒體自己的已驗備份。**

```bash
read -r -p '已核對的 bootfs 分區：' BOOTPART
read -r -p '該案件 extlinux 原始備份絕對路徑：' BACKUP
lsblk -b -o NAME,PATH,SIZE,FSTYPE,LABEL,UUID,MOUNTPOINTS "$BOOTPART"
sha256sum "$BACKUP"
R=$(mktemp -d /tmp/cm6-recovery.XXXXXXXX) || exit 1
findmnt --source "$BOOTPART"
# 上行應無掛載；有自動掛載時先保存狀態並處理，未確認不得繼續。
sudo mount -t ext4 -o ro,noload,nosuid,nodev,noexec "$BOOTPART" "$R" || exit 1
sudo cat "$R/extlinux/extlinux.conf"
sudo umount "$R"
# 確認 UUID、備份 SHA 與差異皆屬本案後才執行寫入回復。
sudo mount -t ext4 -o rw,nosuid,nodev,noexec "$BOOTPART" "$R" || exit 1
sudo install -m 644 "$BACKUP" "$R/extlinux/extlinux.conf"
sudo cmp "$BACKUP" "$R/extlinux/extlinux.conf"
sync
sudo umount "$R"
rmdir -- "$R"
```

**PASS：** 實際完成安全回退或復原媒體啟動演練，回到原版身分、UUID、DTB、基本網路；證據含操作者識別媒體的依據與完整 UART。只有寫好備案但未做演練則 BLOCKED。不要為製造測試而故意斷電損壞系統。

### 重測規則

- 改映像、核心、DTB、韌體或套件，均記新 SHA／版本；一輪只改可追溯的變因。原版與候選不混寫。
- 藍牙首開修正必須**重燒乾淨媒體**，在任何 unblock 前留證；普通 reboot 不能替代。
- 網路修正重跑 eth0、eth1、Wi-Fi 的獨立流量／計數與三次冷開；PHY 修正不可只看連線圖示。
- AI 修正重跑相同模型與 CPU 對照、實際 profile；只有模型不同的成功不能關閉舊模型缺陷。
- 相機停止修正重跑兩個單路、雙路、無重置再開、畫質及幀率；保留原停止警告，不能增加 timeout 後就忽略。
- 散熱修正記新物料／風扇／環境，重跑相同負載；不要拿不同冷卻條件的耗時直接做效能比較。
- SD 與 eMMC 各自完成燒錄、身分、首開、重啟與冷開；單板樣本不代表所有 RAM／載板版本。
