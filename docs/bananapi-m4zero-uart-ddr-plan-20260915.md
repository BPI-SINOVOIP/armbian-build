# 0845：UART 載入 DDR SPL2 的增量計劃

日期：2026-09-15。基準提交：`334dcf6f4b962dafa6e304b24e7b5ad34719c015`。
分支：`bpi-h618-recovery-network-20260915`。使用者同意先更新計劃並推送，再執行本階段。

## 目的與順序調整

在已完成的 SRAM 首驗上，先做不寫媒體的 UART DDR 實驗，提前原 P4 中不依賴 P3 寫卡交易的部分，編號為 P4A。原 P3 更新器、完整多槽布局、eMMC 與多 OS 仍獨立處理，不標示為已完成。

目標是固定救援入口、單一可重新建置的 DDR SPL2、受限執行期參數與可續接結果，使一般參數測試不必反覆編譯、拔卡、重刷 OS。DDR 失敗不要求實驗程式正常返回，主機以已確認的外部電源回到救援。現在只有 0845 的短程 SRAM 證據，不能把 480 或 792 MHz 稱為已證明的安全值。

## 不變條件

- 本次不寫實體 SD／eMMC，不改分割表、SPL1、槽 0 或原 `6.6.75` 系統，不使用槽 1 至 4。
- 使用者確認的目標為 0845、`ttyUSB0`、`bpi-pw-1`；每次重新操作仍核對當前端點、持有者與插座身分，不操作其他設備。
- 先提交本計劃並確認遠端，再做新增工具與實板測試；每個實質階段另記錄結果與提交。
- 原始 UART、設備識別與測試結果只存新建的本機證據目錄，公開 Git 保存去識別摘要、程式、測試與雜湊。
- 不依賴網路持續整合或模型結果宣告實板通過，不更動既有來源／備份／證據。

## 已知相容性門檻

現有 `build-009` 的封包核心固定接受 `kind=1`，主機將它明定為 `smoke`；入口為 `0x30000`，可用執行期區間為 `[0x30000,0x48000)`，共 98,304 B。該空間需容納程式、資料、BSS、堆疊及參數，不是全給程式碼。

正式 DDR 負載必須有不同型別、輸入及結果契約，不能冒充 `smoke` 或把 DDR 成功偽裝為原冒煙標記。若延續此嚴格契約，卡上的舊 SPL1 需要一次受控升級才能接受新型別。**本次先離線建置與驗證，不因此取得寫卡授權。** 升級前須提出備份、兩範圍或其他精確布局、回讀與復原方式；任何超出原授權的範圍另議。

不能直接跳入舊 SPL／原廠 boot0。新版負載需要自己的入口、向量、堆疊、BSS、時基與 UART，不依賴先前 `gd`、DDR 重定位或先成功執行 `sunxi_board_init()`。DDR 程式使用的電源初始化、CPU／匯流排時脈與 MMIO 相依性必須明列。

## 分階段工作與門檻

| 階段 | 工作 | 完成門檻 |
| --- | --- | --- |
| P4A0 | 現有救援的 UART 壞封包、截斷、取消與逾時案例 | 當次載入失敗、不能執行失敗負載、新 nonce 交握恢復；不寫 SD，不用壞槽位做實驗 |
| P4A1 | 固定來源、型別與交接契約 | 列明新版 SPL1 的必要變更及一次性升級門檻；SRAM 配置、保留區與錯誤處理有測試 |
| P4A2 | 既有 DDR 工具移植為獨立 SPL2 | 真實交叉編譯；ELF／MAP／反組譯稽核；無 DDR 執行相依；參數解析與結果協定有正常／拒絕回歸 |
| P4A3 | 0845 的受限實板 DDR 首驗 | 前置相容 SPL1 已另行核准部署；先辨識容量／幾何，再單組測試；失敗可回救援，結果不依賴 DDR 保存 |
| P4A4 | 單變量參數矩陣與續接 | 同二進位換參數、來源與設定雜湊、未完成輪次可續跑；先建立對照再比較 792 MHz；容量與地址覆蓋明列 |

P4A0 不代表所有 SD 故障皆已驗收；不破壞現在的槽 0 來製造媒體故障。UART 封包損壞只在主機私有測試複本產生，正常工具仍須拒絕壞封包；專用故障注入器不得削弱正式上載器守門。

## DDR 實作範圍

沿用既有 DDR 演算法、時序與 M4ZLAB 調參經驗，不重新發明硬體初始化。將原本依賴 bootstrap 的幾何／容量輸入改成可追溯的辨識或核准配置，不把舊安全初始化的結果當成必然存在。

第一版先做一輪一組設定，結果送回 UART 後停止，由主機重新上電再送下一組。可調欄位限已定義的時脈、驅動、ODT、TPR 與測試範圍；不開放任意 MMIO 寫入或未核准的電壓掃描。保留未知欄位、錯誤範圍、容量溢位、地址越界及重複欄位的拒絕。

讀寫測試與效能結果分開：資料圖樣、地址別名、邊界及分散窗口為正確性；效能不能代替零錯誤。2 GiB／4 GiB、rank／匯流排寬度不能由產品名稱或料號印象推定。未覆蓋的範圍必須明說，不把窗口測試當全容量或長時間穩定。

## 自動化與停止條件

- 主機先獨占 UART、核對實體路徑與插座名稱／MAC；每輪包含工作 ID、nonce、設定／程式雜湊、期限、UART 原始資料與結論。
- 故障注入只針對固定測試包；每個案例須先成功交握，失敗後再次握手。連續三次無握手即停止，不無限切電。
- 斷電前若確認是固定 SRAM 程式且未啟動 OS，可依該程式停止契約重啟；若出現 Linux、未知輸出或設備身分不符，停止自動斷電，不能沿用 SRAM 假設。
- 插座命令失敗先查同一目標狀態，不用 `toggle` 補救。過熱／供電保護異常停止；未具備溫度與電氣量測條件不做無界壓力或電壓極限實驗。
- 尚未量測電源軌歸零與 UART 回供電，插座循環只按該觀測範圍記錄，不混作電氣冷啟動驗收。
