# 0845 階段適配器接線

此文件描述 `tools/bpi_lab_h618.py` 的實作範圍，不是新的硬體通過證明。它接入既有真實工具，不匯入 `output/` 內的臨時程式，也不修改歷史報告。

## 已接入與未接入

| 階段 | 行為 | 狀態 |
| --- | --- | --- |
| `preflight` | 重驗完整備份的壓縮摘要，SSH 唯讀核對 RAM 救援、eMMC CID／控制器／容量／未使用狀態、SD 前 4 MiB 與救援身分檔摘要 | 已實作，未以新適配器實板重驗 |
| `deploy` | 先重做目前狀態核對，再呼叫既有部署工具驗來源、串流寫入已授權 userarea、完整寫入範圍回讀及 SD 前後比較 | 已實作，未以新適配器實板重驗 |
| `smoke` | 呼叫既有原配核心／根媒體檢查、雙 CPU 計算、新建暫存檔完整回讀及失敗服務檢查 | 已實作，未以新適配器實板重驗 |
| `boot` | 電源、SRAM 交接、首次登入與客戶 SSH 接入需整合既有原型 | 明確回覆 `blocked` |
| `recovery` | 故障狀態判斷、關機或受控斷電、SRAM 救援及 SSH 重建需整合既有原型 | 明確回覆 `blocked` |
| 中途續作 | 必須重新核對當前媒體與系統狀態，不能只引用舊收據 | 明確回覆 `blocked` |

因此 `whole_adapter_ready=false`。不得現在把它設定成已核定的五階段站點並啟動整批工作。若繞過這個限制，佇列會在未接入階段停止，且不能靠此版適配器自動救援。

## 固定設定

私有設定的 `schema` 為 `bpi-lab-h618-v1`。完整設定檔 SHA-256 必須等於工作中的 `boot_config_sha256`；每次改設定須建立新的工作鍵，不得修改舊嘗試。

| 欄位 | 要求 |
| --- | --- |
| `station_id`、`test_version` | 與工作請求完全相同 |
| `hardware_id` | 此版只接受 `bpi-m4zero-0845`；不是由 SoC 自動識別實體板號 |
| `dependencies` | 程式內 `DEPENDENCIES` 列出的每個工具檔名及 SHA-256；不能省略，也不能從日誌取得程式碼 |
| `backup` | `{path, sha256}`；必須指向已完成的可信 `manifest.json`，同目錄保留原始完整 gzip 備份 |
| `authorization` | `userarea_write=true`、相同 `hardware_id`、`media_identity=cid:<既有0845的CID>` 與人工授權記錄 `record`；不自動產生授權 |
| `sd_prefix` | `{bytes: 4194304, sha256: <核定摘要>}` |
| `rescue_identity_sha256` | 已核定救援 `/etc/bpi-rescue.json` 的 SHA-256，不是任意目前檔案的摘要 |
| `rescue_ssh`、`customer_ssh` | 各含 `config: {path, sha256}` 與 `alias`；必須是先經 UART 配對的嚴格主機金鑰設定 |
| `components` | 以 XZ SHA-256 為鍵、原配組件 `{path, sha256}` 為值；限既有 `bpi-m4z-emac` 格式，最多十套 |
| `output_root` | 已存在的私有證據目錄；每個工作、嘗試與階段建立排他的新目錄 |
| `timeout_seconds` | 60 至 86400 的整數；外層站點期限還須涵蓋這段時間及設定核對 |

入口與設定必須由可信部署環境提供。相依檔摘要有助於追溯及拒絕意外變更，不會使 Python 直譯器、SSH 設定引用的金鑰、函式庫或本機帳號變成隔離沙箱。主機金鑰與密鑰均不提交 Git。

## 操作方式

先由已核定的站點記錄準備私有設定；不要把測試 fixture 的假授權或假摘要填入真實站點。以下只讀本機設定與小型參照檔，不連 SSH、不解壓 XZ、不操作硬體：

```sh
python3 -B tools/bpi_lab_h618.py \
  --config /absolute/private/h618.json \
  --config-sha256 <設定檔SHA256> --inspect-config
```

階段入口由標準輸入接受既有 `bpi-lab-request-v1`，標準輸出僅一份 `bpi-lab-stage-v1` JSON。原始 SSH 輸出與詳細部署／短測證據存到私有證據目錄，不混入契約輸出。不要對新板手動呼叫 `deploy`；只適用之前已授權的 0845 eMMC，且操作者已確認獨立救援與排他使用。完整佇列仍需等 `boot`／`recovery` 的正式接線及資格驗證。

重複嘗試不覆寫既有證據；備份、來源、CID、控制器、容量、SD 前綴或 RAM 救援不符就停止。短測失敗不會改為成功，不會自動減小測試檔、擴充分割區、關閉失敗服務或重試來隱藏原問題。

預檢不是寫入授權的快取。部署 API 透過 `pinned_preflight` 再次接收固定備份摘要、SSH 設定摘要、SD 前綴及救援核心／身分檔摘要；真正遠端部署在開啟目標寫入描述符前必須核對這些條件。SSH 設定在來源驗證後再核對並保存為本次私有唯讀副本，該次 SSH 只讀此副本；其引用的金鑰或其他外部設定仍須由操作員核定。舊部署 API 的未固定模式維持相容，但新適配器不使用該模式。

獨立審查曾重現預檢至部署間的救援身分、備份／SD 前綴及 SSH 設定變更缺口，已在上述寫入前檢查補強；新增遠端替身測試要求錯配時連目標寫入描述符也不能開啟。這是新增軟體守門，不回溯改寫舊實板證據。

## 證據界線

- 本次只有離線回歸，未操作電源、UART、SSH 或媒體。
- 硬體模式的單一階段成功只代表該階段，不能當成原始客戶開機鏈、全部周邊或長時間穩定性通過。
- 既有十套的 RCU／LZMA 間歇失敗、Bookworm 服務失敗及 minimal 空間限制照原紀錄保留。
- 其他 H618 板與其他 SoC 不繼承 0845 的身分、授權或 SRAM 位址；使用另外的板級適配與資格流程。
