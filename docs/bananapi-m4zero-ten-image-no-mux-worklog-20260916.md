## T1：獨立救援建置

在原 0845 Linux 以現有 `6.6.75-current-sunxi64` 核心及模組，於 `/root/bpi-lab/rescue-build-20260916-001` 真正執行 `mkinitramfs`。使用私有 mount namespace 隔離原共享 hooks；只寫新的工作目錄，不改原 `/boot`、SPL1、FIT、槽或 eMMC。

成品 `rescue-initramfs.img` 為 `28133455` 位元組，SHA-256 為 `1bb869de199636881240a4fa25e5d1dfc8fb6e10e246d4d55768a49c48058d24`；回傳主機摘要一致，`gzip -t` 通過。建置報告、清單及日誌回存在 T1 證據目錄，報告 SHA-256 為 `a0874c24ecc2d0f59a001e99c62fb93bf514acb9b6cf5e8a9086f7d675762e55`。

救援工具 17 項離線測試通過。建置曾顯示 brcmfmac 其他晶片韌體缺失警告，原樣保留；成品清單已含這片使用的 BCM43455 韌體及法規資料。是否能冷開機、載入 Wi-Fi 及 SSH，仍以後續實板結果判定，不能僅憑清單宣稱成功。

新增的一次性 U-Boot 載入器先核對既有橋接封包，僅從槽 3 交接；核心、DTB、overlay、救援包載入後比較長度及 RAM CRC32。現有 U-Boot 沒啟用 `hash` 命令，CRC32 僅為傳輸錯誤檢查；可信 SHA-256 由原 Linux 經固定主機金鑰的 SSH 取得，不把 CRC32 說成密碼學驗證。不執行原 `boot.scr` 或保存環境；只套用已核對的 Wi-Fi overlay，不套用未指定的 pin 參數。此路徑的差異屬救援環境，不作客戶原生啟動結果。
