# Banana Pi 映像增量防重與同類批次計畫

日期：2026-09-05

來源分支：`bpi-integration-20260829`

## 一、修正原因

先前作業直接以新來源提交重建 45 塊板、444 個映像，沒有先把中央正式發布區、
先前批次與本輪候選建立全域帳本。中央目錄實際已有舊來源的 45 個板目錄、444
個壓縮映像與 444 個 SHA-256 檔；四路作業另已完成本輪 94 個唯一映像。若不先
盤點，重新啟動整板或全矩陣作業會重做這 94 個項目，因此已停止舊流程。

舊四路啟動器預設停用。未來任何建置都必須先由盤點工具產生唯一待辦佇列，且在
呼叫 `compile.sh` 前再次確認該唯一鍵仍為缺少狀態。

目前矩陣仍是 45 塊板、444 個唯一映像項目。舊正式區是待取代基線，不能抵銷

| 分類 | 映像數 | 處置 |
|---|---:|---|
| 完整 c867 候選 | 80 | 沿用，不再建置 |

| 本輪真正缺少 | 350 | 依整板群組逐項建置 |

完整 c867 候選共有八塊板：`bpi-m1`、`bpi-m1p`、`bpi-m2pro`、`bpi-m2s`、
`bpi-m64`、`bpi-p2z`、`bpi-w2`、`bpi-w3`。其中 M2S 原本停在
`new-installed` 交易階段；已直接使用既有 c867 驗證函式完成十個映像的

另記錄兩個未完成壓縮檔、兩個原始映像、一個空白觸發標記及六個空白舊暫存
目錄。它們都不算完成項目；只有在新正式矩陣完整收斂後，才可依清冊移除。

## 四、唯一鍵與防重規則

映像用途唯一鍵為：

```text
folder / board / branch / release / profile
```

候選建置身分另包含：

```text
source_commit
bsp_base_commit
matrix_sha256
userpatches_sha256
build_context_sha256
```

執行規則如下：

1. 候選項目必須符合固定的來源提交與建置內容雜湊，並具有完成標記、映像、
   同名 SHA 檔及雜湊一致的受控完整日誌，才算本輪完成。
2. 完整候選板必須具有所有預期項目與板級完成標記，才可直接進入整板發布驗證。
3. 部分候選逐項保留；完成該板時只能建置帳本所列缺項，不得整板重來。
4. 既有正式板是可回復基線，不是本輪最新來源成果，不能抵銷本輪待辦。
5. 待辦佇列以外的唯一鍵不得呼叫 `compile.sh`。
6. 每次呼叫建置前重新掃描；若狀態已不是「本輪缺少」，立即停止該項。
7. 每個建置嘗試使用獨立 UUID 日誌，不覆寫先前成功或失敗紀錄。
8. Armbian 內部建置日誌複製到受控狀態目錄並記錄 SHA-256，不依賴會被框架
   輪替的 `output/logs` 原路徑。
   既有 94 個項目則使用已驗證雜湊的完整主日誌，不因內部副本已輪替而重建。
9. 中斷交易若已恢復為完整板，立即返回，不得再次進入映像建置迴圈。
10. 未明確指定板卡時，重建工具預設拒絕執行全矩陣；只有人工明確允許才可解除。

## 五、同類映像順序

實際待建為 350 個項目。依受控矩陣逐板處理，不開四路平行作業；同一板卡的
共用 Kernel、Bootloader 與套件快取可連續使用，且每板固定依下列順序完成：

1. `trixie/minimal`
2. `trixie/xfce`
3. `bookworm/minimal`
4. `bookworm/xfce`
5. `jammy/minimal`
6. `jammy/xfce`
7. `noble/minimal`
8. `noble/xfce`
9. `resolute/minimal`
10. `resolute/xfce`

板卡順序以 `config/bananapi-latest-release-matrix.tsv` 為準。八塊已完成板只做
整板驗證與發布；三塊部分完成板沿用既有項目並補缺；其餘板才執行完整板組。
不能只用 `current`、`legacy`、`vendor` 或 `edge` 推論共用同一套核心。

## 六、收斂流程

1. 重新執行盤點，固定本輪來源提交、建置內容雜湊與 444 列帳本。
2. 完整重驗 94 個候選映像，不重新編譯。
3. 八塊完整候選驗證成功後，逐板以可回復交易取代中央舊板，先釋放空間。
4. 三塊部分完成板只補帳本缺項；整板驗證成功後逐板取代中央舊板。
5. 其餘 34 塊板依矩陣順序逐板建置，每完成一板就驗證並交易式取代舊板。
6. 每板完成後重跑盤點，已完成數只能增加，待辦數只能下降；否則停止作業。
7. 全部完成後，正式區逐項驗證檔名、板卡、分支、發行版、類型、SHA-256、
   XZ 串流與映像唯讀內容，數量必須是 45／444／444。
8. 全域驗證成功後才封存 R1，並依清冊移除中止產物、空白暫存目錄與舊別名。
