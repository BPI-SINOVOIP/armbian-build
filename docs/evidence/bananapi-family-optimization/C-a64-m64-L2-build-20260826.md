# Banana Pi A64 M64 current 候選映像 L2 建置證據

日期：2026-08-26

## 結論

`bananapim64` 已由乾淨來源完整建置 Debian Trixie current minimal CLI，並通過 A64 專用 L2 唯讀守門。候選映像的固定來源、IMG／XZ 同一性、U-Boot／ATF／Crust 啟動鏈、M64 DTB、SD／SDIO／eMMC、AP6212 Wi-Fi／Bluetooth 韌體、USB OTG、Gigabit Ethernet、HDMI／類比音訊、Lima、Cedrus 與標準開發工具均符合本次受控政策。

此結果不代表實體板已完成 UART、冷啟動、記憶體、儲存、無線、Bluetooth、USB、網路、音訊、顯示、GPU、VPU、待機、喚醒或排針驗證；取得實機證據前維持 L2。

## L2 守門範圍

1. 檢查候選矩陣、中繼資料、來源提交、來源樹、建置參數及建置／驗證政策雜湊一致。
2. 驗證固定 Linux、U-Boot、ATF、Crust 與 Armbian firmware 提交；U-Boot 套件另逐欄保存 U-Boot／ATF／Crust 的來源、ref 與 revision。
3. 以唯讀 loop 與 `mount -o ro,noload` 檢查映像，不執行映像內程式。
4. 檢查核心、initrd、`overlay_prefix=sun50i-a64`、七項 A64 overlay 與 `allwinner/sun50i-a64-bananapi-m64.dtb` 的 model、compatible 及檔名身分。
5. 檢查 SD 與 SDIO 為 4-bit、eMMC 為 8-bit／不可移除／具硬體重設，並檢查 USB OTG／host、Bluetooth UART、Gigabit Ethernet、HDMI、音訊與 AXP803 節點。
6. 檢查 BCM43430 Wi-Fi 韌體、校準資料與 BCM43430A1 Bluetooth 韌體雜湊。
7. 檢查 Lima、Cedrus、Allwinner Crypto Engine、音訊、USB gadget mass-storage、Wi-Fi、Bluetooth、GPIO、I2C、SPI、MMC 與網路核心設定。
8. 檢查 `rfkill`、`bluetooth`、`bluez`、`bluez-tools`、`iw`、`ethtool`、`usbutils`、`alsa-utils`、`smartmontools`、`gpiod`、`i2c-tools`、`python3-libgpiod`、`python3-spidev` 與 `v4l-utils` 已安裝。

核心設定、模組、DT 節點、韌體或工具存在只證明軟體已封裝，不等同相關硬體路徑可用。648 MHz DRAM、Crust 電源管理、GPU、VPU、USB gadget 與無線功能仍必須經實機確認。

## L3 實機門檻

- 執行至少 30 次完整斷電冷啟，保存 UART 全程日誌及失敗率。
- 分別驗證 SD 與 eMMC 開機、安裝、交互啟動順序及斷電檔案系統一致性。
- 驗證不同記憶體與 eMMC 批次在 648 MHz DRAM 設定下的冷啟動、重啟、長時間壓力及溫度邊界。
- 驗證 Wi-Fi、Bluetooth、Gigabit Ethernet、USB host、OTG gadget mass-storage、HDMI、類比音訊、Lima OpenGL ES 與 Cedrus V4L2 解碼。
- 驗證 GPIO、I2C、SPI、UART、1-Wire、PPS、待機、喚醒與板卡實際引出的介面。
