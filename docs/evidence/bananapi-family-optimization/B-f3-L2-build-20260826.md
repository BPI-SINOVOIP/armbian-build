## 結論

`bananapif3` 已由乾淨來源完整建置 Debian Trixie current minimal CLI，並通過 SpacemiT K1 專用 L2 唯讀守門。此結果證明候選映像的來源、IMG／XZ 同一性、SpacemiT 啟動載荷、F3 DTB、核心功能與標準開發工具符合本次受控政策。

此結果不代表實體板已完成 UART、SD／eMMC 開機、記憶體、網路、無線、顯示、相機、40-pin 或硬體加速驗證；取得實機證據前維持 L2。

## L2 守門範圍

1. 檢查候選矩陣、中繼資料、來源提交、來源樹、建置參數及驗證設定雜湊一致。
2. 驗證 Linux、U-Boot、OpenSBI 固定提交及 `esos.elf` 雜湊與建置後來源證據一致。
3. 以唯讀 loop 與 `mount -o ro,noload` 檢查映像，不執行映像內程式。
4. 比對四個映像內啟動載荷的偏移、長度與 U-Boot 套件實際位元組。
5. 驗證兩個只供封裝或燒錄流程使用的套件載荷大小、雜湊與可散布權限。
6. 檢查分割區起點、核心、initrd、extlinux 與 `spacemit/k1-bananapi-f3.dtb` 的 model、compatible 及檔名身分。
7. 檢查儲存、Ethernet、USB、PCIe、GPIO、I2C、SPI、PWM、UART、視訊、圖形、Wi-Fi、Bluetooth 與 USB gadget mass-storage 核心能力。
8. 檢查 `gpiod`、`i2c-tools`、`python3-libgpiod`、`python3-spidev`、`v4l-utils`、`pciutils`、`nvme-cli`、`usbutils`、`alsa-utils`、`iw` 與 `ethtool` 已安裝。

核心設定、模組、DT 節點或工具存在只證明軟體已封裝，不等同相關硬體路徑可用。

## L3 實機門檻

- 執行至少 30 次完整斷電冷啟，保存 UART 全程日誌及失敗率。
- 分別驗證 SD、eMMC、SPI-NOR 與救援燒錄路徑。
- 驗證不同記憶體與儲存配置的冷啟動、重啟、長時間壓力與溫度邊界。
- 驗證 Ethernet、Wi-Fi、Bluetooth、USB host、USB gadget 與斷線重連。
- 驗證 HDMI／MIPI 顯示、相機、GPU、視訊編解碼與音訊的實際資料路徑。
- 驗證 GPIO、I2C、SPI、UART、PWM 與欲發布介面的實體迴路、腳位衝突及電壓域。
