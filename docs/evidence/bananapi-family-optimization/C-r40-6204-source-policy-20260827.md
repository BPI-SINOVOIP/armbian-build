# Banana Pi BPI-6204 legacy 來源與候選政策

日期：2026-08-27

## 結論

BPI-6204 目前只提供 `legacy` 核心目標，因此本批次以 Linux 6.12.90 建立 Debian Trixie minimal CLI 候選，不將它併入 R40 `current` 的 M2 Berry／M2 Ultra 政策。既有 6204 映像只能作歷史參考，不能直接提升為 L2，因為新增 DTS 的 unified diff hunk 宣告 341 行、實際來源有 376 行，核心只取得前 341 行，造成 UART0／3／4／5／7 與 USB PHY 尾段遺失。

本次把 DTS hunk 修正為完整 378 行，並補上 SPI1 的 PI pinmux 與 CS1 pinmux。修正版已在固定 Linux 提交上通過 patch 套用及獨立 DT 編譯；尚未建立候選映像，也沒有實機驗證，因此板卡目前仍為 L0。

| 項目 | 舊版 | 修正版 |
| --- | --- | --- |
| DTS 行數 | 341 | 378 |
| DTB SHA-256 | `0a92964739cb958b4faa224bfc6448e6180ae89a8617c7f6ae5286dc2943f9f8` | `266250249d06a6d217b20d13663b33af6b831d69b9dcd77247d1ea58e5554e11` |

| UART0／3／4／5／7 | `disabled` | `okay` |

使用同一套 `cpp` 與 `dtc -@` 流程重建舊 341 行 DTS，產物雜湊與歷史 Linux DTB 套件完全一致；因此修正版 DTB 預期雜湊可在建置前納入政策。裝置樹編譯時仍有 R40 上游既存的 unit-address 與 interrupt-provider 警告，本次未擴大處理範圍。

## L2 候選守門

候選政策位於：

```text
config/validation/bananapi-sunxi-r40-6204-legacy.json
```

守門要求包括：

1. DOS／MBR 第一分割區從 sector 8192 開始；`sfdisk` 的 `dos` 與 U-Boot 中繼資料的 `msdos` 會正規化為同一格式。
2. 比對 U-Boot 套件的 `u-boot-sunxi-with-spl.bin` 與映像 8192 byte 偏移，並檢查固定來源及 R40、MMC、SATA、USB、Ethernet 設定。
3. 檢查 SD 4-bit、SDIO 4-bit、eMMC 8-bit，並固定 eMMC 為 25 MHz、3.0 V、禁止 1.8 V，避免進入未驗證的 DDR52 路徑。
4. 檢查 SATA、Gigabit Ethernet、HDMI、USB host、MCP2515 CAN、EEPROM、兩顆 RTC、五組 UART、Lima、Cedrus、Crypto Engine 與相關核心選項。
5. 檢查 CAN、網路、SATA、USB、GPIO、I2C、SPI、影像與感測器工具已安裝。

Wi-Fi 只保留 SDIO 與電源時序設定；因 DTS 未固定模組型號與 Bluetooth UART 子節點，本批次不宣稱內建 Wi-Fi／Bluetooth 已支援。HDMI 節點啟用也不等同 HDMI 音訊或實際顯示已通過。

## 實機門檻

- 以 UART 保存至少 30 次完整斷電冷啟及失敗率。
- 分別驗證 SD 與 eMMC 開機、安裝、重啟及斷電一致性。
- 驗證 MCP2515 CAN 收發、SPI1 CS1 與中斷腳位，不只檢查介面存在。
- 驗證 SATA SMART／I/O 壓力、Gigabit Ethernet、全部 USB host、HDMI 與顯示穩定性。
- 驗證五組 UART、EEPROM、DS1340、ISL1208、GPIO、PWM、Lima 與 Cedrus。
- 取得實際 Wi-Fi／Bluetooth 模組料號後，再新增具來源與雜湊的韌體政策。
