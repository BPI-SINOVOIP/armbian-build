# Banana Pi M7 current 候選映像 L2 建置證據

日期：2026-08-26

## 結論

`bananapim7` 已由乾淨來源完整建置 Debian Trixie current minimal CLI，並通過 Rockchip RK3588 專用 L2 唯讀守門。此結果證明候選映像的來源、IMG／XZ 同一性、雙 U-Boot payload、固定 RKBin 啟動依賴、M7 DTB、核心功能與開發工具符合本次受控政策。

此結果不代表實體板已完成 UART、SD／eMMC／NVMe／SPI-NOR 開機、記憶體、網路、無線、顯示、音訊、相機、40-pin 或硬體加速驗證；取得實機證據前維持 L2。

## L2 守門範圍

1. 檢查候選矩陣、中繼資料、來源提交、來源樹、建置參數及驗證設定雜湊一致。
2. 驗證固定 RKBin 提交、DDR、BL31、RockUSB 載入器雜湊與建置後證據清單一致。
3. 以唯讀 loop 與 `mount -o ro,noload` 檢查映像，不執行映像內程式。
4. 分別比對映像 32768 bytes 與 8388608 bytes 偏移的 `idbloader.img`、`u-boot.itb` 套件 payload。
5. 檢查核心、initrd、`overlay_prefix=rockchip-rk3588` 與 `rk3588-bananapi-m7.dtb` 的 model、compatible 及檔名身分。
6. 檢查 SD 4-bit、eMMC 8-bit，以及 GPU、VOP、HDMI0、PCIe、USB、UART、PWM 與溫度節點設定。
7. 檢查 Panthor／Panfrost、Rockchip DRM、Hantro、RGA、VDEC、NVMe、R8169、BRCMFMAC、Bluetooth、音訊與 USB gadget mass-storage 核心能力。
8. 檢查 `rfkill`、`bluetooth`、`bluez`、`bluez-tools`、`gpiod`、`i2c-tools`、`python3-libgpiod`、`python3-spidev`、`v4l-utils`、`pciutils`、`nvme-cli`、`usbutils` 與 `alsa-utils` 已安裝。

核心設定、模組、DT 節點或工具存在只證明軟體已封裝，不等同相關硬體路徑可用。

## L3 實機門檻

- 執行至少 30 次完整斷電冷啟，保存 UART 全程日誌及失敗率。
- 分別驗證 SD、eMMC、NVMe、SPI-NOR 與 Maskrom／RockUSB 救援路徑。
- 驗證不同記憶體容量的冷啟動、重啟、長時間壓力與溫度邊界。
- 驗證雙 2.5GbE、Wi-Fi、Bluetooth、USB host、Type-C gadget 與斷線重連。
- 驗證 HDMI／DP、GPU、VPU、RGA、NPU、音訊與相機的實際硬體加速及資料路徑。
- 驗證 GPIO、I2C、SPI、UART、PWM 與欲發布 overlay 的實體迴路、腳位衝突及電壓域。
