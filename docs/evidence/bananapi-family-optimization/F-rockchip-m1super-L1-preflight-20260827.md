# Banana Pi M1 Super L1 完整映像預檢證據

## 結論

第一次完整映像預檢成功完成 `compile.sh`、XZ 壓縮、XZ 串流同一性與映像唯讀內容檢查。這證明固定 Linux、U-Boot、RKBin 與韌體來源可以走完完整 Armbian 映像流程，也提供了分割區、檔案系統、DTB 與最終設定的精確契約。

本次仍維持 L1。建置開始時的來源提交是 `e11ac67a60479ab564d1944d5b5ccbdc1d0ccbdb`，但建置期間主工作樹又加入文件提交，後段 `RKBIN_STATUS.json` 因讀取當下的 `HEAD` 而記錄到另一個提交。專用驗證器正確拒絕這個來源提交競態。唯讀內容檢查是在相同舊提交的暫時工作樹完成，不能取代原子性的正式來源證據，也不代表實機、量產或公開發布通過。

## 已修正方向

1. 專用建置入口固定並拒絕覆寫 `SOURCE_DATE_EPOCH=1787082913`。
2. Rockchip 共用建置器從 `CANDIDATES.tsv` 取得建置提交，並在後段證據前後拒絕 `HEAD` 改變。
3. L1 專用驗證入口只產生 L1 狀態，不再預設寫成 L2。
4. 共用驗證器新增根檔案系統型別守門，並固定分割區、DTB、最終設定與載荷大小。

## 證據限制

- 沒有執行 UART 開機、SD／eMMC 冷啟動、重啟或斷電循環。
- 沒有驗證記憶體、儲存、網路、Wi-Fi、藍牙、HDMI、影音、USB 或 40-pin 實體功能。
- Wi-Fi 量產料號仍有文件矛盾，韌體逐檔散布授權尚未完成。
- 只有第二次固定提交與時間戳的完整建置通過專用驗證後，才可考慮升為內部 L2；L2 仍不得對外發布或宣稱硬體通過。
