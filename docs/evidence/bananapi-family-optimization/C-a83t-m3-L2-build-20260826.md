# Banana Pi A83T M3 current 候選映像 L2 建置證據

日期：2026-08-26

## 結論

`bananapim3` 已由乾淨來源完整建置 Debian Trixie current minimal CLI，並通過 A83T 專用 L2 唯讀守門。此結果證明候選映像的固定來源、IMG／XZ 同一性、板級 U-Boot 載荷、M3 DTB、SD／SDIO／eMMC、AP6212 Wi-Fi／Bluetooth 韌體、USB OTG、Gigabit Ethernet、HDMI／類比音訊與標準開發工具符合本次受控政策。

此結果不代表實體板已完成 UART、冷啟動、記憶體、儲存、無線、Bluetooth、USB、網路、音訊、顯示或排針驗證；取得實機證據前維持 L2。主線 M3 DTB 沒有 GPU 節點，因此本候選不宣稱 OpenGL ES 硬體加速。板上的 SATA 連接埠經 USB-to-SATA 橋接，不可表述為原生 AHCI SATA。

## L2 守門範圍

1. 檢查候選矩陣、中繼資料、來源提交、來源樹、建置參數及驗證設定雜湊一致。
2. 驗證固定 Linux、U-Boot 與 Armbian firmware 提交，以及 U-Boot 套件與映像載荷位元組一致。
3. 以唯讀 loop 與 `mount -o ro,noload` 檢查映像，不執行映像內程式。
4. 檢查核心、initrd、`overlay_prefix=sun8i-a83t` 與 `allwinner/sun8i-a83t-bananapi-m3.dtb` 的 model、compatible 及檔名身分。
5. 檢查 SD 與 SDIO 為 4-bit、eMMC 為 8-bit／不可移除／具硬體重設，並檢查 USB OTG／host、Bluetooth UART、Gigabit Ethernet、HDMI、音訊、PMIC 與 IR 節點。
6. 檢查 BCM43430 Wi-Fi 韌體、校準資料與 BCM43430A1 Bluetooth 韌體雜湊。
7. 檢查 Cedrus、音訊、USB gadget mass-storage、Wi-Fi、Bluetooth、GPIO、I2C、MMC 與網路核心設定。
8. 檢查 `rfkill`、`bluetooth`、`bluez`、`bluez-tools`、`iw`、`usbutils`、`alsa-utils`、`gpiod`、`i2c-tools`、`python3-libgpiod`、`python3-spidev` 與 `v4l-utils` 已安裝。

核心設定、模組、DT 節點、韌體或工具存在只證明軟體已封裝，不等同相關硬體路徑可用。上游 U-Boot 的 480 MHz DRAM、A83T eMMC 校準與 USB mass-storage 設定也必須經實機確認。

## L3 實機門檻

- 執行至少 30 次完整斷電冷啟，保存 UART 全程日誌及失敗率。
- 分別驗證 SD 與 eMMC 開機、安裝、交互啟動順序及斷電檔案系統一致性。
- 驗證不同記憶體與 eMMC 批次在 480 MHz DRAM 與 MMC 校準設定下的冷啟動、重啟、長時間壓力及溫度邊界。
- 驗證 Wi-Fi、Bluetooth、Gigabit Ethernet、USB host、OTG gadget mass-storage、HDMI、類比音訊與 Cedrus V4L2 解碼。
- 驗證 GPIO、I2C、SPI、UART、IR 與板卡實際引出的介面。
