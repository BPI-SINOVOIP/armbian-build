# Banana Pi M2 Plus H3 候選映像 L2 建置證據

日期：2026-08-26

## 結論

`bananapim2plus` 已由乾淨來源完整建置 Debian Trixie current minimal CLI，並通過 L2 唯讀守門。此結果證明候選映像的來源、壓縮同一性、板級 U-Boot、H3 DTB、核心功能、overlay 與板級工具符合本次受控政策。

此結果不代表實體板已完成 UART、SD 冷啟動、eMMC、Wi-Fi、Bluetooth、網路、HDMI、GPU、VPU、USB、音訊或 40-pin 驗證；取得實機證據前維持 L2。

## L2 守門範圍

1. 檢查候選矩陣、中繼資料、來源提交、來源樹、建置參數與政策雜湊一致。
2. 以唯讀 loop 與 `mount -o ro,noload` 檢查映像，不執行映像內程式。
3. 比對映像 8 KiB 偏移與套件內 `u-boot-sunxi-with-spl.bin` 的實際位元組。
4. 檢查核心、initrd、`overlay_prefix=sun8i-h3`、預設 `analog-codec` 與板級 DTB 身分。
5. 檢查 SD、SDIO Wi-Fi、eMMC、Ethernet、HDMI、顯示引擎、OTG 與三組 USB host 節點處於啟用狀態。
6. 檢查 SD 控制器為 4-bit，並確認 15 個 H3 I2C、SPI、UART、PWM、USB host、音訊及 1-Wire overlay 已封裝。
7. 檢查 Lima GPU、Sun4i DRM、Cedrus VPU、Crypto、Wi-Fi、Bluetooth、MMC、Ethernet、I2C、SPI、PWM 及 USB gadget mass-storage 核心設定。
8. 檢查 `rfkill`、`bluetooth`、`bluez`、`bluez-tools`、`gpiod`、`i2c-tools`、`python3-libgpiod`、`python3-spidev` 與 `v4l-utils` 已安裝。

overlay 存在只證明映像提供可選功能；腳位衝突的 overlay 不應同時啟用，仍須依實際接線選擇。

## L3 實機門檻

- 執行至少 30 次完整斷電冷啟，保存 UART 全程日誌及失敗率。
- 驗證 SD、eMMC、GBE、板載 Wi-Fi 與 Bluetooth 的穩定度、吞吐與長時間壓力。
- 驗證 HDMI 多解析度、Lima OpenGL ES、Cedrus V4L2 解碼、音訊輸入輸出與 CPU 使用率。
- 驗證 USB host、OTG gadget mass-storage、GPIO、I2C、SPI、UART、PWM 與 1-Wire 實體迴路。
- 分別驗證每個欲發布的 overlay；不可由檔案存在推論外接裝置已通過。
