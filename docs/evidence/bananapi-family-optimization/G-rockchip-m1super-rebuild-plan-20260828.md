# Banana Pi M1 Super 現行提交重建計畫

日期：2026-08-28

## 目的

提交 `8c6533a10c3ec97e0565c46ef34ab857fca7d4d4` 的完整映像曾通過內部 L2 軟體守門，但它早於目前全板最佳化分支。現行分支不能只因檔名及硬體契約相同，就把舊 IMG、XZ、狀態或 validation 證據當成新提交的重建結果。

本階段先保留舊映像及其 SHA-256 作歷史證據，將現行狀態降回 L1，再依下列程序建立新提交的正式 L2：

1. 固定 M1 Super 唯一輸出目錄；外部 `OUTPUT_DIR` 不同時立即拒絕，且不得先寫入狀態檔。
2. 政策工具預設只執行 `source-contract`；物質稽核必須明確選擇 `historical` 或 `live`。
3. L1 校準時可完整建置映像及執行共用唯讀驗證，但不得產生正式 L2 物質完成狀態。
4. 由校準實檔固定 GPT、DTB、最終設定、`idbloader.img`、`u-boot.itb` 與來源投影後，提交並推送契約。
5. 移除校準輸出及專用 OverlayFS 上層，從乾淨且已推送的新提交正式重建。
6. 正式驗證只使用 `live` 證據；共用唯讀守門與專用物質重查全部通過後，才原子寫入完成狀態。
7. 最後才把 validation、中央盤點與文件提升為 L2，並再次執行全倉回歸。

## 執行進度

2026-08-28 已從提交 `29861f5be` 完成 L1 校準建置與共用唯讀驗證。精確載荷、DTB、GPT、最終設定及 RKBin 清單均與原契約一致，詳見 `H-rockchip-m1super-L2-calibration-20260828.md`。

目前 validation 已進入 L2 正式重建契約，但尚未宣稱映像完成，也沒有內嵌物質證據；中央盤點仍維持 L1。下一步是提交並推送本契約，安全刪除校準輸出與 M1 Super 專用 OverlayFS 上層，再從新提交乾淨重建。

## 歷史產物處理

舊輸出目錄不得在原地局部覆寫。正式校準前會把整個目錄原子改名，名稱包含來源提交 `8c6533a10`；IMG、XZ、雜湊、矩陣、完成狀態、驗證狀態及日誌一同保留。新正式 L2 完成且歷史摘要已在 Git 內閉合後，才評估是否回收歷史大型映像。

## 證據邊界

- 本計畫不宣稱任何實機開機或周邊功能通過。
- RKBin 仍只能依授權隨採用 Rockchip 積體電路的平台散布，不得獨立散布或修改。
- Armbian firmware 逐檔授權與量產 Wi-Fi／Bluetooth BOM 尚未閉合。
- M1 Super 板檔維持 `.wip`；公開發布與硬體聲明一律維持禁止。
