# M4ZLAB2 在 1116 板的跨板驗證證據

## 結論

1116 使用與 0438 相同的 `M4ZLAB2` SPL 及 792 MHz 候選，完成 64 組乾淨
記錄。480 MHz 保險設定與 792 MHz 跨板候選各完成 `M2 10/10`，全部通過。

```text
1116 geometry：4,096 MiB、2 Rank、x32、16 Rows、10 Columns
480 MHz 保險設定 M2：10/10 通過
792 MHz 跨板候選 M2：10/10 通過
1116 原廠動態 TPR 同板對照 M2：5/5 通過
跨板熱重設候選：通過
冷開機、Linux 與量產驗收：尚未通過
```

## 跨板候選

0438 與 1116 共用設定：

```text
clk=792
dx_odt=0x07070707 dx_dri=0x0e0e0e0e ca_dri=0x00000d0d
odt_en=0xaaaaeeee
tpr6=0x3a808080 tpr10=0x402f6663
tpr11=0x24242422 tpr12=0x110f1111
```

機器可讀設定：

```text
tools/bpi-m4zero-ddr-lab-profile-cross-board-candidate-792.json
```

0438 與 1116 各自為 `M2 10/10`，合計 `20/20`。這是跨兩片 4 GiB 板的
熱重設候選，不是量產共同值。

## TPR6 共同窗口

1116 的關鍵邊界：

| `tpr6[31:24]` | 層級 | 結果 |
| --- | --- | ---: |
| `0x2d` | M2 | 3/3 |
| `0x2e` | M2 | 3/3 |
| `0x3a` | M2 | 10/10 |
| `0x44` | M2 | 3/3 |
| `0x45` | M2 | 1/3 |
| `0x46` | M1 | 0/3 |
| `0x47` | M2 | 0/3 |
| `0x48` | M2 | 0/3 |

0438 的 `0x2d` 為 4/5，故排除；1116 的 `0x45` 為 1/3，亦排除。兩板共同
已觀察零失敗區間為 `0x2e..0x44`。其整數中點約為 `0x39`，採用的 `0x3a`
位於中心附近，且與 1116 原廠動態選點一致。

區間內不是每個值都做相同次數的 M2，因此此處稱「已觀察共同區間」，不稱
完整眼圖。弱板與其他顆粒批次仍可能縮小該區間。

## 原廠同板對照

從既有 1116 原廠 UART 取得的動態結果為：

```text
tpr6=0x3a808080
tpr11=0x25252523
tpr12=0x110f0f10
```

把這三個值帶入相同實驗器後完成 `M2 5/5`。這證明原廠結果與目前開源 DDR
流程可相容，但不代表開源程式已重現原廠完整 read/write training。跨板候選
採用 0438 lane 掃描中心 `0x24242422/0x110f1111`，因其已在兩片板各完成十次。

## 後續 gate

1. 把跨板設定帶回標準 U-Boot，恢復 TF-A、U-Boot proper、核心及 initrd。
2. 在 0438、1116 及已知弱板各執行完整斷電冷開機，不能只使用 watchdog。
3. 核對 initrd 搬移前後雜湊，確認先前 1116 的解包錯誤不再出現。
4. 進入 Linux 後執行全容量記憶體壓測、儲存 I/O、重啟及溫度矩陣。
5. 納入 2 GiB 板、更多 4 GiB 序號與電壓角落後，才可提出量產設定。
