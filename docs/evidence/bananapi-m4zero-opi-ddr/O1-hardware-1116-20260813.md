# O1 在 1116 板的第一次硬體證據

## 結論

這次 UART 證明 `1116` 板在 O1 靜態 792 MHz 設定下完成 DDR 初始化、
geometry 探測、TF-A、U-Boot 與 Linux 核心交接。Linux 核心隨後回報：

```text
Initramfs unpacking failed: no cpio magic
```

擷取到此結束，沒有 rootfs、userspace 或登入證據。因此分類為：

```text
O1 結構化 DDR 診斷：通過
單次 SPL／TF-A／U-Boot：通過
單次 Linux 完整開機：未通過
792 MHz 穩定性：未通過驗收
硬體測試可追溯性：資料不完整
```

## initrd 離線排除

從 O1 可燒錄映像的 ext4 分割區唯讀取出：

```text
/boot/uInitrd-6.18.32-current-sunxi64
```

驗證結果：

| 項目 | 結果 |
| --- | --- |
| uImage 大小 | 21,293,041 bytes |
| uImage SHA-256 | `77e1014b6ebb33786a4c689072a47a35e41b0b5b5e7f34df6c086e81647b1e6b` |
| gzip payload 大小 | 21,292,977 bytes |
| gzip SHA-256 | `9917880d351531cb1641b78f7367b53cc28c515052a6e127cc0a6b0d691b23b2` |
| `dumpimage -l` | 通過，資料 CRC `0xb7f66fe6` |
| `gzip -t` | 通過 |
| 解壓格式 | ASCII cpio、SVR4、無 CRC |
| `cpio -t` | 通過，共 1,163 項 |

U-Boot 在 UART 也先回報 initrd checksum 通過，然後把 initrd 從載入位置
搬到 `0x48bb1000`，核心才回報無 cpio magic。由於磁碟內 archive 完整，且
映像除 bootloader 區間外與可開機 U0 payload 逐位元相同，主要假設是
792 MHz 下搬移後或核心讀取期間的 DRAM 資料不可靠。這仍是推論，不可在
沒有同板重複測試或搬移前後 CRC 證據時宣稱已確定根因。

## 可追溯性缺口

1. `1116` 來自測試交接情境，UART 不會自行輸出實體貼紙板號。
2. 沒有斷電 10 秒、上電與擷取結束事件，不能由檔案獨立證明完整冷開機。
3. 沒有實際燒錄映像 SHA-256 或燒錄後 SD 回讀雜湊；Build ID 只能證明
   bootloader 身分吻合，不能證明整張 SD 與候選映像逐位元一致。
4. 沒有 DDR 絲印、eMMC、SD 卡、電源與線材資訊。
5. 外部交接文件記錄的 UART mtime 有小數奈秒，但檔案系統實際值為整秒。
6. UART 結束於 initramfs 錯誤，沒有擷取正常結束事件。

因此本證據不能納入 O5 冷開機成功率，只能用於 O1/O3 診斷。
