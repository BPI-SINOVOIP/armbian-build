# M4ZLAB2 在 0438 板的參數掃描證據

## 結論

板號 `0438` 在同一份 `M4ZLAB2` SPL 下完成 531 組執行期 DDR 實驗。480 MHz
保險設定與 792 MHz 單板中心候選各完成 `M2 10/10`，均為零失敗，且每次
測試後都成功恢復 480 MHz 並重新進入實驗器。

目前分類如下：

```text
0438 單板熱重設參數掃描：完成
480 MHz 保險設定 M2：10/10 通過
792 MHz 單板中心候選 M2：10/10 通過
792 MHz 冷開機與 Linux 壓力測試：尚未執行
跨板及量產共用設定：尚未成立
```

本結果證明執行期搜尋方向成立，但不等於客戶要求的 792 MHz 量產驗收。

以最少三個相同 M2 樣本重新排名，共有 252 組不同參數及 18 組全數通過

benchmark 不足以代表 DDR 峰值效能。頻率掃描兩端仍通過，因此
`maximum_margin_candidate` 正確保持空值，672 MHz 只列在有截尾標記的
`widest_observed_candidate`，不作最大容錯結論。

第一次連線時，既有 `minicom` 程序同時讀取 `/dev/ttyUSB0`，造成兩筆同步
錯誤及一次逾時。停止該程序後重新建立上述乾淨檔；爭用期間檔案另保留於
`output/evidence`，沒有納入本報告的 DDR 統計。

## 整體候選

### 480 MHz 保險設定

```text
clk=480
dx_odt=0x07070707 dx_dri=0x0e0e0e0e ca_dri=0x00000e0e
odt_en=0xaaaaeeee
tpr6=0x44000000 tpr10=0x402f6663
tpr11=0x24242624 tpr12=0x0f0f100f
```

結果為 `M2 10/10`。這是目前 0438 的最低風險保險設定，但尚未執行斷電
冷開機、溫度、電壓及 Linux 長時間壓力矩陣。

### 792 MHz 單板中心候選

```text
clk=792
dx_odt=0x07070707 dx_dri=0x0e0e0e0e ca_dri=0x00000d0d
odt_en=0xaaaaeeee
tpr6=0x3a808080 tpr10=0x402f6663
tpr11=0x24242422 tpr12=0x110f1111
```

結果為 `M2 10/10`。可直接使用：

```text
tools/bpi-m4zero-ddr-lab-profile-0438-candidate-792.json
```

`odt_en=0x9988eeee` 的同參數替代組也完成 `M2 5/5`；兩者計時差異低於可用
解析度，保留既有且跨來源較常用的 `0xaaaaeeee`，不以微小數值差異換設定。

## 邊界結果

### 頻率與 TPR6

基準參數在 480、528、600、672、720、744、768、792 MHz 的 M0、M1、M2
各完成三次，三個層級都是 `24/24`。這只證明該單板可完成各頻率實驗，不能
由內建 CPU load/store 迴圈宣稱峰值記憶體頻寬。

792 MHz 的 `tpr6` 深度測試結果：

| 值 | M2 結果 |
| --- | ---: |
| `0x2d808080` | 4/5 |
| `0x2e808080` | 5/5 |
| `0x2f808080` | 5/5 |
| `0x30808080` | 5/5 |
| `0x3a808080` | 5/5 |
| `0x44000000` | 2/2 |
| `0x47808080` | 5/5 |
| `0x48808080` | 0/3 |

因此 `0x2d` 與 `0x48` 已觀察到失敗，`0x3a` 位於兩端之間且與 1116 原廠
動態結果一致。中間不是逐一掃完所有值，所以只能稱為受測範圍中心候選，
不能稱完整類比眼圖。

### TPR11 與 TPR12

工具以 `tpr11.b0..b3` 及 `tpr12.b0..b3` 分別替換 6-bit lane 欄位，避免把
整個 32-bit packed 值作線性加減。邊界重複測試顯示多個 lane 在低端或
高端已有 1/3、2/3 的間歇失敗，最後取各 lane 受測窗口中段：

```text
tpr11=0x24242422
tpr12=0x110f1111
```

這組與 `tpr6=0x3a808080` 合併後完成 792 MHz `M2 10/10`。單一 lane 的
稀疏掃描不能證明 lane 之間完全獨立；跨板測試仍須使用完整合併設定。

### 驅動與 ODT

| 欄位 | 0438 的受測結果 | 採用值 |
| --- | --- | --- |
| `dx_odt` | 每值三次零失敗集合為 `0x03..0x0c`、`0x10..0x14`；`0x00..0x02`、`0x0d..0x0f` 及 `0x15` 失敗 | `0x07` |
| `dx_dri` | `0x00..0x05` 失敗；`0x06..0x1f` 粗掃通過，`0x06`、`0x0e`、`0x1f` 重複通過 | `0x0e` |
| `ca_dri` | `0x0a` 與 `0x10` 各 0/3；`0x0b` 與 `0x0f` 各 3/3 | `0x0d` |
| `odt_en` | `0x9988eeee`、`0xaaaaeeee` 各 M2 5/5；其他三組離散 mask 出現失敗 | `0xaaaaeeee` |

`dx_odt` 呈現兩段離散合法集合，不是線性延遲窗口，因此不以兩端算術平均
產生不存在的「中心」。`dx_dri` 到 5-bit 上限仍通過，沒有高端失敗邊界，
所以保留既有 `0x0e`，不宣稱 `0x1f` 較佳。

## 限制與下一步

1. 全部候選都是同一次上電後的 watchdog 熱重設，不是完整斷電冷開機。
2. 目前只有 0438 一片板，不能外推到 1116、弱板或其他 Rayson 批次。
3. M2 以 8 MiB 分散窗口和 Rank 邊界檢查為主，不能取代 Linux 全容量壓測。
4. 內建 benchmark 受 CPU 迴圈限制，744 與 792 MHz 的差異約 0.2%，不足以
   作為峰值效能排名證據。
5. 尚未記錄溫度、供電壓降、冷熱循環、SD 卡及電源批次。

下一階段先在第二片板重跑 480 與 792 完整候選，再對兩板共同失敗邊界取
交集；只有跨板通過後，才建立可開機 U-Boot 候選並進行冷開機與 Linux
壓力測試。
