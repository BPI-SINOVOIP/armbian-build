# M5 Pro edge 修補集相容修正紀錄

日期：2026-09-06

## 結論

增量映像管線在完成 228／444 個映像後，首次停於 `bananapim5pro / trixie / edge / minimal`。Linux 來源仍正確固定於 7.0.14 提交 `458c6079fc1d41d564c37679c8ace02cd83ee817`，但整併新版 Armbian 後，通用 edge 選到 `archive/rockchip64-7.1`，導致三個以 7.1 原始碼為基準的修補無法套用至 7.0.14。

本次不升級 M5 Pro 核心，也不重建已完成映像。修正方式是恢復先前完整建置通過的 `archive/rockchip64-7.0` 修補集合，並由 M5 Pro 板級 hook 明確固定該目錄。此變更只處理 M5 Pro 的固定核心與修補集不一致，不改變其他 Rockchip 板卡的 edge 政策。

## 修正來源

`patch/kernel/archive/rockchip64-7.0` 從提交 `566819421` 恢復，共 338 個檔案、1,915,490 bytes。逐檔 `git hash-object` 與該提交的樹物件比對結果為 338／338 相同，且仍排除已被 Linux 7.0.14 納入的過時序列埠修補 `general-serial-8250-fix-sysrq-break-dw-apb.patch`。

## 續跑策略

1. 原來源提交已完成且驗證有效的映像維持不變，不重新編譯。
2. 第一階段以原來源提交續跑，透過 `DEFER_FOLDERS=bpi-m5pro` 只延後 M5 Pro；壓縮、整板交易與其餘項目照原架構、發行版、類型順序完成。
3. 第二階段從已推送的相容修正提交完整建置 M5 Pro 的 10 個映像，第一個項目強制重建 U-Boot、Kernel、ATF 與適用元件，其餘項目只沿用同一修正提交產生的快取。
4. 最後逐項核對來源提交、建置內容雜湊、映像 SHA-256、XZ 串流、唯讀內容與整板交易狀態；不同來源提交不得在未記錄政策下互相冒充。

## 逐板來源守門

`audit-bananapi-release-state.py --candidate-input-policy <TSV>` 可對矩陣內每個 `folder` 指定唯一允許的 `source_commit` 與 `build_context_sha256`。政策檔必須完整覆蓋 45 塊板，不可重複、不可含矩陣外目錄，也不得與全域來源限定同時使用。輸出目錄會保存實際套用的 `候選輸入政策.tsv`，作為最終發布證據。

```text
folder\tsource_commit\tbuild_context_sha256
bpi-m5pro\t<40 位提交>\t<64 位建置內容雜湊>
```

## 驗證限制

本紀錄證明來源、修補套用、完整建置與發布產物可重現，不等同 M5 Pro 實機的 DDR、SD／eMMC、網路、顯示、GPU、VPU、NPU、USB、PCIe 或 40-pin 已完成 L3 驗收。硬體結論仍須使用實板、UART 與周邊測試證據。
