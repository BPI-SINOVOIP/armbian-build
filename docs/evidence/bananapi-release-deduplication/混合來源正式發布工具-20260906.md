# 混合來源正式發布工具紀錄

日期：2026-09-06

## 目的

本輪完整矩陣包含 45 塊板、444 個映像。44 塊板沿用已驗證的來源提交與建置內容雜湊，`bpi-m5pro` 則必須使用修正 Linux 7.0 修補集後的新提交。為避免不同來源在只有檔名與數量相符時被誤認為同一批次，本次加入逐板政策、候選交易殘留守門與可回復的正式發布提升交易。

## 新增工具

### 逐板政策產生器

`tools/generate-bananapi-candidate-input-policy.py` 只接受完整候選狀態。它會依受控矩陣核對每塊板的板級完成標記、全部項目完成標記、來源提交、建置內容雜湊與預期項目數，再依矩陣順序原子寫入政策 TSV。

```bash
python3 tools/generate-bananapi-candidate-input-policy.py \
  --matrix config/bananapi-latest-release-matrix.tsv \
  --candidate-state /media/pi/SMCI/bpi/bananapi-state-c8673931c96c \
  --output /media/pi/SMCI/bpi/bananapi-state-c8673931c96c/candidate-input-policy.tsv
```

### 候選狀態稽核

`tools/audit-bananapi-release-state.py` 在逐板政策模式下，同時驗證項目與板級完成標記。它另輸出 `候選交易殘留.tsv`，把未收斂的交易狀態、原始映像標記及 `.staging-*`、`.previous-*`、`.failed-*` 目錄列入待辦；進行中的合法狀態可被後續工作續作，但不能通過最終零待辦 Gate。

### 逐板發行說明

`tools/generate-bananapi-release-notes.py` 依受控矩陣與實際候選檔名，為每塊板原子建立 `Release-Notes-zh-TW.md`。內容記錄板卡代號、發行版、分支、每個映像的檔名核心標籤、CLI／XFCE 變體、檔案驗證、燒錄、首次啟動與證據限制。檔名中的 `0` 不當成實際 Linux 版本，實機版本須以 `uname -r` 核對。工具不會把軟體候選延伸宣稱為實機、量產或散布授權通過；既有說明只有在明確加入 `--replace` 時才會被取代。

```bash
python3 tools/generate-bananapi-release-notes.py \
  --matrix config/bananapi-latest-release-matrix.tsv \
  --candidate-release /media/pi/SMCI/bpi/bananapi-release-c8673931c96c
```

### 正式發布提升

`tools/promote-bananapi-candidate-release.sh` 預設只預演。它會先核對矩陣、映像唯一性、SHA-256 邊車、實際雜湊、45 份繁體中文發行說明、逐板政策稽核輸出與零交易殘留；板目錄只允許映像、同名 SHA 邊車與受控發行說明。加入 `--execute` 後，工具只在同一檔案系統建立候選檔案的硬連結 staging，再以目錄原子更名切換完整正式版本；舊正式版本保留為可回復的 previous，候選原件不會被修改。跨檔案系統、鎖衝突或任何預檢失敗都會拒絕交易。

建置器與提升器共同使用位於發布根目錄外的固定鎖：`<父目錄>/.<發布目錄名稱>.build.lock`。這把鎖不會隨正式目錄更名而改變 inode，因此正式路徑尚未建立、被切換至 previous，或新正式目錄剛完成切換時，新版建置器都不能插入交易空窗。根目錄內的 `.latest-rebuild.lock` 則作為舊版工具相容防線：收斂器從更新候選說明前就同時持有候選與舊正式相容鎖，提升器再把受鎖的正式鎖 inode 硬連結到新 staging。切換後的正式目錄因此仍指向同一個受鎖 inode，直到正式重新稽核結束前，只認舊相容鎖的建置器也無法寫入。固定鎖與相容鎖都必須是實體一般檔案，開啟後會再核對 FD 路徑與 inode，符號連結或開啟期間被替換都會被拒絕。

```bash
tools/promote-bananapi-candidate-release.sh \
  --candidate-release /media/pi/SMCI/bpi/bananapi-release-c8673931c96c \
  --formal-release /media/pi/SMCI/bpi/google-drive-upload/2026/2026.08 \
  --matrix config/bananapi-latest-release-matrix.tsv \
  --audit-output /media/pi/SMCI/bpi/bananapi-state-c8673931c96c/audits/final-mixed-source
```

預演與完整稽核通過後，才以相同參數加入 `--execute`。

### 全矩陣收斂

`tools/finalize-bananapi-mixed-source-release.sh` 把逐板政策、45 份繁體中文說明、候選完整稽核、提升預演、正式提升與正式重新稽核串成單一受控流程。它先持有候選增量佇列鎖，再持有候選與正式發布的固定外部鎖直到流程結束；因此兩次稽核與提升之間沒有合作程序可寫入候選或正式內容。

可設定 `VERIFICATION_WORKERS` 為 1 至 16，預設為 1；例如設為 4，讓獨立檔案的
雜湊與 XZ 串流檢查並行。每個檔案仍執行完整驗證，稽核輸出順序維持不變，任何
驗證失敗都會阻止正式提升。直接呼叫稽核器時對應選項為 `--verification-workers`。

工具會把受控矩陣與四個必要工具複製到本輪輸入快照，記錄每個快照的 SHA-256 與發布後仍有效的相對路徑，後續步驟只讀取同一快照。候選、狀態與正式目錄若相同、互相包含、指向系統根目錄或跨越無法原樣回復暫存目錄的檔案系統，會在任何候選說明或正式內容變更前拒絕執行。候選與正式稽核不只比對總列數，還會逐鍵確認板目錄、板卡、分支、發行版、類型、來源提交與建置內容雜湊精確覆蓋受控矩陣，重複鍵或以錯誤項目湊滿 444 列都不能通過。

正式舊目錄內只允許自動移出空的 `.staging-*`；工具會先登記原路徑與封存路徑，再以同檔案系統更名把原目錄完整封存於本輪證據，不以重建空目錄冒充復原，也不會在更名後才登記而留下訊號中斷空窗。舊正式目錄中的矩陣外板目錄可在候選稽核中列帳，因為它們會連同舊正式版本進入 previous；提升後的正式稽核仍強制矩陣外項目為零。

提升器在建立硬連結 staging 或移動任何正式目錄前，先以暫存檔更名發布 `提升提交標記.tsv`，內含正式、previous 與 staging 的受控絕對路徑，狀態依序為「準備」、「已備份」與「已提交」。若子程序在任一目錄建立或更名後遭強制終止，父程序會依日誌路徑與實際目錄狀態判斷是尚未切換、只移出舊正式版本，或新正式版本已就位，再封存中斷 staging 或復原 previous；不以「尚未收到子程序成功回傳」誤判為「正式目錄尚未切換」。拓撲復原只會在本輪已實際呼叫正式提升後啟用，因此提升前檢查發現的既有 previous 或 staging 只會保留現場並停止，不會被誤認為本輪交易。若本輪日誌遺失或格式損壞，父程序只在受鎖正式父目錄內恰好存在唯一 previous、唯一或零個 staging，且正式路徑型態與可回復交易拓撲一致時自動處理；任何多重、連結或模稜兩可的狀態都保留現場並以失敗退出。

正式重新稽核或後續最終 Gate 失敗時，工具會把未核准的新正式目錄移開，再復原 previous；這是可回復的目錄交易，不對兩次更名之間不存在讀取空檔作不實保證。子程序只有在正式版本已回到交易前狀態且 staging 已安全清理後，才移除交易日誌；若無法移走新正式版本，會保留日誌、previous 與現場供父程序接手。復原成功後才安全清除仍可由候選重建的失敗硬連結；任一空 staging 無法原樣放回時也會改以失敗退出。正式發布根目錄在 `realpath` 正規化前即拒絕符號連結，避免連結指向被誤當成實體發布根目錄。成功輸出命名為 `final-<UTC>-<PID>`；失敗輸出命名為 `failed-final-<UTC>-<PID>`，並具有以暫存檔更名發布的 `執行狀態.tsv`。最終輸出目錄發生名稱衝突或更名失敗時，保留在隱藏 staging 的狀態檔會重寫為實際的失敗碼，不得繼續宣告成功，也不會把衝突路徑的不明內容當成本工具證據。

```bash
TOOL_REPO="$PWD" \
MATRIX_FILE="$PWD/config/bananapi-latest-release-matrix.tsv" \
CANDIDATE_RELEASE=/media/pi/SMCI/bpi/bananapi-release-c8673931c96c \
CANDIDATE_STATE=/media/pi/SMCI/bpi/bananapi-state-c8673931c96c \
FORMAL_RELEASE=/media/pi/SMCI/bpi/google-drive-upload/2026/2026.08 \
VERIFICATION_WORKERS=4 \
tools/finalize-bananapi-mixed-source-release.sh
```

## 完成條件

1. 逐板政策必須精確包含矩陣內 45 塊板。
2. 45 個板級完成標記與 444 個項目完成標記都必須符合各板政策。
3. 候選目錄必須正好包含 444 個 `.img.xz` 與 444 個同名 `.img.xz.sha`。
4. 每塊板必須具有一份由實際矩陣產物產生的繁體中文發行說明。
5. 全部映像必須通過 SHA-256 與 XZ 串流驗證。
6. 待辦佇列、中止產物、舊暫存目錄、矩陣外項目及候選交易殘留都必須為零。
7. 正式提升後必須再次完整稽核，確認正式目錄與候選內容一致。
8. 建置器與提升器必須共同持有發布根目錄外的固定鎖，並讓新舊正式目錄的根內相容鎖指向同一受鎖 inode，根目錄切換不得產生新舊建置器可寫入的空窗。
9. 收斂流程必須使用同一份矩陣與工具快照；成功與失敗輸出必須可由機器明確區分，子程序完成目錄切換後也必須有可驗證的提交標記。
10. 正式重新稽核未通過時，必須自動復原提升前正式版本，不得讓未核准內容留在正式路徑；交易日誌遺失或損壞時也必須由唯一安全拓撲復原，否則保留現場並拒絕宣告完成。

## 證據限制

上述工具只證明來源身分、軟體建置、檔案完整性與發布交易可追溯。它不代表 45 塊板均已完成實機啟動、全部介面、長時間壓力、量產或對外散布授權驗證；各板既有 Gate 仍然有效。
