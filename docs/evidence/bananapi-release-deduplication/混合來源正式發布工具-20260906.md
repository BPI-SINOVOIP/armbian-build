# 混合來源正式發布工具紀錄

日期：2026-09-06

## 目的

本輪完整矩陣包含 45 塊板、444 個映像。44 塊板沿用已驗證的來源提交與建置內容雜湊，`bpi-m5pro` 則必須使用修正 Linux 7.0 修補集後的新提交。為避免不同來源在只有檔名與數量相符時被誤認為同一批次，本次加入逐板政策、候選交易殘留守門與可回復的正式發布提升交易。

## 新增工具

### 逐板政策產生器

`tools/generate-bananapi-candidate-input-policy.py` 只接受完整候選狀態。它會依受控矩陣核對每塊板的板級完成標記、全部項目完成標記、來源提交、建置內容雜湊與預期項目數，再依矩陣順序原子寫入政策 TSV。

```bash
python3 tools/generate-bananapi-candidate-input-policy.py \
  --matrix config/bananapi-latest-release-matrix.tsv \
  --candidate-state /media/pi/SMCI/bpi/bananapi-state-c8673931c96c \
  --output /media/pi/SMCI/bpi/bananapi-state-c8673931c96c/candidate-input-policy.tsv
```

### 候選狀態稽核

`tools/audit-bananapi-release-state.py` 在逐板政策模式下，同時驗證項目與板級完成標記。它另輸出 `候選交易殘留.tsv`，把未收斂的交易狀態、原始映像標記及 `.staging-*`、`.previous-*`、`.failed-*` 目錄列入待辦；進行中的合法狀態可被後續工作續作，但不能通過最終零待辦 Gate。

### 正式發布提升

`tools/promote-bananapi-candidate-release.sh` 預設只預演。它會先核對矩陣、映像唯一性、SHA-256 邊車、實際雜湊、逐板政策稽核輸出與零交易殘留。加入 `--execute` 後，工具只在同一檔案系統建立候選檔案的硬連結 staging，再以目錄原子更名切換完整正式版本；舊正式版本保留為可回復的 previous，候選原件不會被修改。跨檔案系統、鎖衝突或任何預檢失敗都會拒絕交易。

```bash
tools/promote-bananapi-candidate-release.sh \
  --candidate-release /media/pi/SMCI/bpi/bananapi-release-c8673931c96c \
  --formal-release /media/pi/SMCI/bpi/google-drive-upload/2026/2026.08 \
  --matrix config/bananapi-latest-release-matrix.tsv \
  --audit-output /media/pi/SMCI/bpi/bananapi-state-c8673931c96c/audits/final-mixed-source
```

預演與完整稽核通過後，才以相同參數加入 `--execute`。

## 完成條件

1. 逐板政策必須精確包含矩陣內 45 塊板。
2. 45 個板級完成標記與 444 個項目完成標記都必須符合各板政策。
3. 候選目錄必須正好包含 444 個 `.img.xz` 與 444 個同名 `.img.xz.sha`。
4. 全部映像必須通過 SHA-256 與 XZ 串流驗證。
5. 待辦佇列、中止產物、舊暫存目錄、矩陣外項目及候選交易殘留都必須為零。
6. 正式提升後必須再次完整稽核，確認正式目錄與候選內容一致。

## 證據限制

上述工具只證明來源身分、軟體建置、檔案完整性與發布交易可追溯。它不代表 45 塊板均已完成實機啟動、全部介面、長時間壓力、量產或對外散布授權驗證；各板既有 Gate 仍然有效。
