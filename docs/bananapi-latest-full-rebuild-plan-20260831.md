# Banana Pi 全系列最新映像重建與替換計畫

日期：2026-08-31

來源分支：`bpi-integration-20260829`

來源提交：`8893355b34efc97a1e7677c6541beb177ec014e1`

## 一、目標

以全系列整合分支的最終提交重新建置所有目前具備 L2 可重建條件的 Banana Pi 板卡，產生精簡命令列版與 XFCE 桌面版映像。每張板卡的新矩陣必須完成原始映像唯讀內容檢查、XZ 串流檢查及 SHA-256 驗證後，才可原子替換中央交付目錄的舊矩陣。

本作業不得先刪除唯一舊映像。新矩陣失敗時保留舊矩陣與可重現日誌；新矩陣通過後才移除該板舊矩陣與工作目錄中的重複映像。

## 二、範圍

- 44 個非 EOS 的 L2 產品板卡：41 個板卡各建置五個發行版、兩種映像，共 410 個映像。
- `bananapicm6`、`bananapif3`、`bananapism10`：RISC-V 64 位元不支援 Bookworm，各建置四個發行版、兩種映像，共 24 個映像。
- `bananapim4zeroemac`：作為 M4 Zero 的獨立功能變體，建置十個映像。
- 預定最新矩陣合計 45 個目錄、444 個 `.img.xz` 與 444 個同名 SHA-256 校驗檔。

`bananapir1` 已是 `.eos`，只保留於歷史封存區，不重新包裝成現行最新支援映像。中央最新矩陣以 `bananapim4zeroemac` 取代原本 R1 所占的目錄位置。

下列三個 L0 產品板卡不產生會誤導使用者的 donor 映像：

- `bananapicm2`：目前只有 R2 Pro 軟體參考，缺少專屬模組與載板 DTS。
- `bananapim2c`：需要可攜 Unisoc／Yocto 來源、修補序列與受控簽署鏈。
- `bananapim4super`：目前只有 ArmSoM Sige3 donor 設定，缺少專屬硬體資料與 DTS。

## 三、建置規則

1. 每板第一個 Trixie 精簡映像使用 `ARTIFACT_IGNORE_CACHE=yes`，重新產生該板 U-Boot、Kernel 與板級套件。
2. 同板其餘發行版可使用第一個映像產生的有效來源與套件快取，避免無意義地重複編譯相同核心十次。
3. 命令列映像使用 `BUILD_MINIMAL=yes`；桌面映像使用 XFCE 與 `DESKTOP_TIER=mid`。
4. 新原始映像先以唯讀 loop 裝置掛載根檔案系統，確認 `armbian-release`、核心與開機目錄存在。
5. 原始映像通過後壓縮成 XZ，重新計算 SHA-256，執行完整 `xz -t`，然後移除原始映像。
6. 每板所有項目完成前，新檔只放在同檔案系統的暫存目錄；不得覆蓋中央舊矩陣。

## 四、空間與替換規則

- 中央目錄：`/media/pi/SMCI/bpi/google-drive-upload/2026/2026.08`。
- 逐板完成後，先將舊目錄改名為回退目錄，再將新暫存目錄改名為正式目錄。
- 正式目錄再次通過數量、檔名、SHA-256 與 XZ 檢查後，才刪除回退目錄。
- 工作樹 `output/images` 根目錄中同板的舊 IMG、XZ、校驗與文字副本，在中央替換成功後移除。
- 被版本化政策測試引用的歷史證據，必須等新契約改指最新產物並通過回歸後才可刪除。
- 快取只刪除明確可重建的失效項目；固定下載來源、私有材料與唯一證據不納入自動清理。

## 五、續跑與失敗處理

- 工具以來源提交建立固定狀態目錄，逐映像與逐板寫入完成標記。
- 中斷後重新執行會重驗已完成項目，從第一個缺少或失敗項目續跑。
- 任一映像建置、掛載、壓縮或校驗失敗，該板不替換舊目錄。
- 失敗不阻擋其他獨立板卡繼續建置；最後彙整第一個有效錯誤與修正結果。
- 整個矩陣完成後重新執行全系列程式回歸、全量 XZ／SHA-256 驗證與磁碟盤點，再提交並推送結果文件。

## 六、完成條件

1. 45 個可建置目錄的每個預期矩陣項目都有本次來源提交的成功建置日誌。
2. 中央目錄只保留各板最新矩陣，不保留被新版取代的舊映像。
3. 444 個壓縮映像全部通過 SHA-256 與 XZ 串流驗證。
4. 三個 L0 板卡保留正確阻擋原因，不以 donor 映像冒充完成。
5. 建置摘要、失敗摘要、來源提交、產物數量與空間變化可追蹤。
6. 自動化工具、測試與最終結果已提交並推送至 `bpi-integration-20260829`。
