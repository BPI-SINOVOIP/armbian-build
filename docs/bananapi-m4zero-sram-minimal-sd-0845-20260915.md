## 授權與改變的條件

使用者回到現場，改先驗證 M4 Zero，確認板號為 **0845**，並明確同意：先備份前 4 MiB，再只更新其中的 SPL1 與第 0 號槽，保留原系統。這是針對本次卡片的縮限實驗授權，不是往後任意改寫對照卡、整卡重刷或電源控制的授權。

本機盤點發現已插入的卡不是空卡：容量約 64 GB、MBR 單一 Linux 分割區從 LBA 8192（4 MiB）開始，內有 Armbian `25.2.2` 與核心 `6.6.75-current-sunxi64`。先前禁止直接覆寫對照卡的原則仍適用；本次因使用者明確接受縮限修改，才進行受控備份及兩個範圍的部署。不改分割表、不清卡、不以完整實驗映像蓋掉既有系統。

板號來自使用者確認，不是本工具讀取的 HW_ID。CID、精確容量與裝置號另外綁定本機證據，不放入公開文件。

## 工具與操作分離

`tools/bpi_sram_sd_minimal.py` 限定 Linux、原生 SD、固定 `build-009`，不是通用燒錄器。三個明確動作如下：

1. `prepare`：核對預先指定 CID／容量／主次裝置號，拒絕 eMMC、掛載、swap、holders 及根磁碟；排他唯讀開啟。兩次讀取前 4 MiB，解析 MBR 並對照核心分割區資訊；將原始／預期前綴與固定產物排他保存、持久化及回讀。分割區首尾各 1 MiB 只作唯讀抽查。
2. `apply`：要求明確寫入旗標及可信 `prepared.json` 雜湊；重新核對身分、布局、備份和原卡內容。排他開啟後，每筆寫入前再檢查，處理短寫，持久化及刷新後回讀。最後前 4 MiB 須逐位元等於預期，白名單以外三段雜湊與分割區抽查均須不變。
3. `restore`：另行明確指定同一份備份與核對條件，只以反向次序恢復兩個範圍。白名單外或抽查分割區已改變即停止，不自動回灌整段，也不猜測如何恢復其他資料。

實際命令的 CID、容量及裝置號由本機核對紀錄帶入，不能把當場讀到的新值自動當成預期值。若出現部分寫入、同步或回讀失敗，保留失敗紀錄，禁止拔卡試跑；先核對原卡身分再進行明確復原。

這次備份**不是整卡備份**。前綴比對與分割區首尾抽查不代表整個 64 GB 已逐位元驗證，也無法涵蓋 SD 控制器、FTL 故障或斷電造成的其他損壞。既有系統分割區是以不向其範圍發出寫入的方式保留。

## UART 與冷啟動驗收

目前本機有兩個同型 CH340；同名 `by-id` 只列出其中一個，不能據此認定另一個不存在。必須核對 `by-path` 與板卡實際接線，不從 `ttyUSB0`／`ttyUSB1` 編號猜測。

1. SD 完成回讀後，才由使用者插回 0845；先確認 UART 為 3.3 V、共地、TX／RX 正確及無電源回灌，再上電。
2. 以 115200、8N1、無流量控制保存完整冷啟動輸出；首要標記為 `BPI-SUP1 event=ready`、`ddr=off`、`sd_write=off`。沒有輸出只能記為待定位，不能直接歸因 DDR。
3. 完成啟動紀錄後才交由 `bpi_sram_uart.py probe` 操作；工具會清除接收緩衝，所以不能用它取代冷啟動錄製。禁止兩個程序同時讀串口。
4. 先 UART 載入不執行，再完整載入與執行交接測試。每次結果核對新 nonce；不得直接傳裸 SPL2 或 eGON 代替 `BPISRAM1` 封包。
5. 經重新上電確認救援可重入後，才測槽 0；主機使用 `--timeout 15`，避免和韌體 10 秒截止時間相同而誤判。

```bash
python3 -B tools/bpi_sram_uart.py load-slot \
  --port "$BPI_CONFIRMED_UART" --slot 0 --timeout 15 --run
```

成功要有同 nonce 的 `loaded result=0`、`handoff entry=00030000`，以及 `BPI-SPL2 event=smoke` 中 `el=3 ddr=off result=pass`。只有載入或交接訊息不算通過；SPL2 測試程式完成後停止，不返回 Linux 或救援菜單，需要再次上電。
