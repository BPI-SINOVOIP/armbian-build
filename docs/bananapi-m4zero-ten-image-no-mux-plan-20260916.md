# M4 Zero 十套客戶映像自動測試：免 SD 切換器修訂計畫

日期：2026-09-16。分支：`bpi-h618-recovery-network-20260915`。

## 執行順序更新

使用者要求以實際測完映像為優先，後續需擴至 400 多套及其他板型。本節取代下文原訂「十次冷啟動及一小時獨立救援壓測後才部署」的先後順序，不把縮短流程說成長測已通過。

1. 0845 的完整 eMMC 備份已核對，使用者明確授權覆寫 userarea；SD、boot0、boot1、RPMB 不動。
2. 原系統同一 A1 引導基線的一小時負載已完成。先以一次獨立 RAM 救援開機、媒體身分及可用傳輸為部署條件，立即實測一套 Bookworm minimal 的部署、完整回讀、客戶核心開機、基本功能與回救援。
3. 先打通上述完整循環再依序跑十套基本驗證；重複冷啟動、故障注入及長測另排，不逐套重建救援或重做整碟原始備份。
4. 以板型／硬體修訂、實際開機組件與映像 SHA-256、測試版本識別工作；保留失敗及部分完成狀態，符合相同條件的已完成項目不重跑。
5. 擴展時共用排程、傳輸、結果格式，板型另提供媒體身分、救援入口及引導介面；不同 SoC 不套用 H618 的位址或 MMC 編號。新板型先做一次完整循環，再批次測 OS。

本機目錄已盤點 45 個板別、444 個壓縮映像；十套 EMAC 已完成完整來源核對。這不代表其餘 434 套已完成內容稽核，也未宣稱其他板型已有可用救援路徑。詳細實測結果以執行紀錄為準。

## 1. 使用者決策與目標

使用者明確不採用 SD 切換器。取消以新增切換治具作為開工條件，沿用已插在 0845 的 SD、UART、可控電源與板載 eMMC。目標是自動依序驗證十套客戶映像，不是再建立與驗收無關的大型救援平台。

本計畫最初僅修訂流程，已依要求先推送，後續經授權進入實機執行。原始客戶壓縮映像不改寫、不重新打包；測試工具、工作副本與證據另存。即時進度以狀態 JSON 及執行紀錄為準，不把最初規劃狀態當成目前狀態。

本文件優先定義十套映像工作的施工順序；[免拔卡環境](bananapi-m4zero-unattended-lab-20260916.md)及[整合計畫](bananapi-h618-recovery-network-plan-20260915.md)中的既有實板證據與安全限制仍有效。HW_ID、多板共用映像、PXE 與 NFS 不再阻塞這項工作。

## 2. 採用架構

```text
主機：十套唯讀原始映像、可信雜湊、測試排程與證據
  ├─ UART：控制、登入、完整開機紀錄
  ├─ 已核對的電源：逾時後受控冷重啟
  └─ 已驗證的網路：映像及大檔傳輸

板子上電 → SD 固定 SRAM 入口，等待主機一次性選擇
  ├─ 救援路徑：獨立且已驗證的 DDR／韌體 → 救援 Linux
  │    └─ 核對 eMMC → 寫入一套映像 → 完整回讀 → 記錄可試跑
  ├─ 系統路徑：受控 U-Boot → eMMC 該映像的核心／DTB／initramfs／根系統
  └─ 開機鏈實驗：匹配該映像的 SPL／TF-A／U-Boot，另做受控橋接
```

SD 的固定入口不隨十套映像更新。救援核心及最小 initramfs 優先作為原 SD 檔案系統內的獨立檔案，載入後以 RAM 為根系統；不假定現有 128 KiB SRAM 槽能容納完整救援 Linux，也不要求重新分割現有 SD。若現有引導無法可靠載入，先證明替代載入路徑，不能直接覆蓋固定 FIT 解決。

eMMC 一次只部署一套，完成後由救援系統換下一套，不分十個固定分割區、不在板上保留十份解壓映像。主機保留原檔與紀錄；每次寫入前核對解壓長度能容納於 eMMC。客戶映像不一定天然可從 eMMC 啟動，須逐套檢查根裝置設定及早期驅動。

## 3. 驗證必須分成兩層

| 層級 | 執行內容 | 可以下的結論 | 不可以下的結論 |
| --- | --- | --- | --- |
| 系統層 | 救援引導載入該映像原配套核心、DTB、initramfs、模組與根系統 | 此組件在已記錄引導條件及 eMMC 上的開機、功能與穩定性 | 原映像 SPL、DDR 初始化、TF-A 或原生 SD 啟動已通過 |
| 開機鏈層 | 固定入口後選用該映像匹配的 SPL、TF-A、U-Boot，再進入其系統 | 受控橋接下該組合的初始化及交接結果 | BootROM 原樣讀取客戶 SD 或原生 eMMC 冷啟動已通過 |

兩層都納入最終報告，不能以第一層完成冒充整套開機鏈完成。先完成系統層端到端流程，不讓任意版本 SPL 的適配阻塞所有 OS 測試；開機鏈層另列施工及完成狀態。系統層也須核對該映像的 DT overlay、開機參數及腳本行為，任何為保護救援而略過的步驟均列為覆蓋缺口；不能只在救援 Linux 執行 `switch_root` 就宣稱測到客戶核心。

現有橋接只驗證特定 A1 SPL／FIT，且 SPL 經重新編譯改讀 FIT 磁區 2048。不能直接載入任何客戶 SPL 就跳轉，也不能假定它會自動改讀 eMMC。新增適配必須核對入口、SRAM 覆寫、BootROM 傳入資訊、媒體編號、FIT 偏移與記憶體保留；需重編時明列差異與二進位雜湊。無法適配的組合記為未完成，不暗中改用共用 A1 後算通過。

原映像以相同位元組寫入 eMMC，只證明部署內容一致，不代表執行路徑與 SD 相同。載入參數、DT 修正、首次設定、工具安裝、擴容或 GPT 調整全部獨立記錄；需要修改的工作副本不稱為原樣執行。若根 UUID 與救援 SD 重複，必須明確消除選錯媒體的風險並記錄差異，不能任由 UUID 搜尋碰運氣。

## 4. 每套的自動流程

1. 主機取得排他設備鎖，核對板號、UART、電源配對及持久進度；不依據檔名推斷已通過。
2. 從固定入口進入救援，核對救援版本、DDR 組合、SD 與 eMMC 身分、掛載及 swap；eMMC 不作救援根系統。
3. 核對可信清單及來源映像。可經網路分段或串流解壓寫入 eMMC，任何截斷、網路錯誤或雜湊不符都保持不可試跑狀態。
4. 寫完同步，再由儲存裝置回讀完整映像長度核對雜湊，不能只對 RAM 快取或下載串流計算。處理舊 GPT 尾部等殘留時須明列寫入範圍，不能宣稱整碟未變。
5. 主機先持久記錄一次性試跑，再冷啟動、選定測試路徑。從上電前開始錄 UART；核對核心、組件雜湊、實際根裝置及 eMMC CID，不接受默默回退至救援 Linux 的假成功。
6. 先記錄原始首次開機，再設定測試帳號／部署必要工具。所有調整列入差異清單，分開報告原始開機與加工具後的壓測。
7. 執行適用測項並保存命令、退出碼與原始輸出。網路失效仍可從 UART 判定；無回應時先留存逾時證據，再由主機斷電、回到 SRAM 救援。
8. 正常結束先關機；異常強制斷電明列可能的檔案系統損傷。故障後不相信舊進度或半寫候選，由救援重新檢查／完整重寫後再試。
9. 保存結果再進下一套。重試有上限，偶發成功不能抹掉前次失敗；失敗副本的必要證據須先保存，不能直接覆寫掉唯一失敗資料。

候選 kernel 或 rootfs 卡死不應阻止主機回固定 SRAM 入口，但這依賴救援 SD 未被破壞、電源切斷有效、無 UART／USB 回灌等實板條件。救援 Linux 無法啟動時，SRAM 仍是診斷入口，不等於當下就能大量重寫 eMMC。

## 5. 媒體與救援保護

- 現有紀錄只證明 eMMC 約 29.1 GiB，沒有分割區顯示不等於沒有資料。首次整碟寫入前須完成盤點、離機原始備份與雜湊及回復方法核驗，並取得可覆寫該 eMMC 使用者區的明確確認；先前可改 SD 帳密不等同 eMMC 清除授權。
- 日常只寫 eMMC 使用者區；不修改開機分割區、RPMB、OTP／eFuse 或不可逆 EXT_CSD 欄位。每次核對 CID、容量、控制器路徑，不硬編 Linux 與 U-Boot 相同 MMC 編號。
- 候選不掛載 SD 救援分割區，既有安裝器、擴容與 bootloader 更新腳本先做靜態稽核。禁止在此矩陣執行會改寫 SD 引導區的命令；必要軟體唯讀限制須留差異紀錄。
- 軟體唯讀不是硬體防寫，不能保證任意有權限程式或硬體故障下永不拔卡。不得為追求原樣測試而偷偷取消固定救援入口。
- 不以「A1 可登入」宣稱救援 DDR 長期可靠。先完成已選救援配置的重複冷啟動、記憶體負載及媒體回讀；失敗時先修復救援基線，不在不穩定 DDR 下繼續燒錄客戶系統。
- 資料傳輸只使用實測可用的 Linux 網路。本輪 RAM 救援 Wi-Fi 冷啟動及候選系統有線 SSH 已實測；介面、速率與限制見執行紀錄，不推論其他板型或擴充硬體版本通過。UART 僅作控制與小檔救援；沒有可靠大量傳輸通道時停止部署。

## 6. 施工階段與驗收

| 階段 | 工作 | 完成證據 | 本次狀態 |
| --- | --- | --- | --- |
| T0 | 固定十套目錄、完整檔名、大小、壓縮與解壓雜湊、OS／桌面、板型及開機組件 | 十筆唯一清單，來源可追溯，缺項及重複明列 | 已完成：EMAC `6.18.49` 十套 |
| T1 | 現有 SRAM 入口接獨立救援系統、穩定 DDR 與網路 | 冷啟動、救援身分、負載及回讀結果 | RAM 救援與網路已實測；冷返回沿用本矩陣證據，獨立記憶體長測仍待做 |
| T2 | eMMC 盤點備份、受限部署器與拒絕測試 | 錯碟、超容量、截斷、雜湊錯誤皆拒絕；授權與回復紀錄 | 備份核對、覆寫授權與實際部署已完成；實際備份還原未驗證 |
| T3 | 一套 CLI 的系統層端到端、逾時與中斷恢復 | 可開機測試；故意缺檔及中斷部署後仍能回救援並重做成功 | 首套循環及真實候選停滯後回救援已驗證；未做完整故障注入矩陣 |
| T4 | 十套系統層基本測試，再做重啟／混合長測 | 十套各自報告及原始紀錄，失敗／不適用／未測分開 | 基本批次執行與分項結果見即時紀錄；桌面、周邊及長測未完成 |
| T5 | 按實際開機組件雜湊分組適配 SPL／TF-A／U-Boot，再配對各 OS | 引導差異、DDR 參數、各組交接與長測結果；失敗回 SRAM | 待做；目前不可宣稱任意 SPL 支援 |
| T6 | 彙整十套結果、覆蓋範圍與對客戶可用的結論 | 系統層與開機鏈層分列，原生 SD 缺測及硬體限制明列 | 唯讀摘要與階段紀錄已可用；不是對外穩定性認證 |

T1 的建議最小門檻為 10 次冷啟動與 1 小時記憶體負載及暫存檔回讀，僅作部署前門檻，不宣稱量產穩定。T4 建議每套 10 次冷啟動、10 次正常重啟與至少 8 小時混合負載；0845 的長時間當機問題另安排至少 24 小時重現測試。這些是待執行門檻，不是既有通過結果，也不能證明永不當機。

適用測項包括 CPU／DDR、eMMC、USB、Wi-Fi／藍牙及實際具備的乙太網路；XFCE 另驗顯示、桌面及 GPU 實際渲染器。GPIO／I2C／SPI、觸控、影音需周邊與迴路證據，缺硬體記為未測。單片 0845 不能代表全部 DDR 型號或其他板型。

## 7. 進度與續作契約

每次工作鍵包含原始映像 SHA-256、板號、測試計畫版本、實際引導組件雜湊及必要治具配置。狀態至少區分待處理、部署中、回讀通過、試跑中、通過、失敗、不適用及未測；每次試跑另有唯一識別與開始／截止時間。

進度、UART 與命令結果即時保存於主機，不只留在待覆寫的 eMMC。重新開始時先核對已完成證據，不能因檔案存在就當成功，也不重跑符合相同條件且證據齊全的項目。基線或腳本變更須明列失效範圍。

每階段更新文件與進度並推送；不把客戶整套映像、帳密或私密原始日誌提交到 Git。後續完成狀態必須依本輪實際證據更新，不把舊離線測試數量當成本計畫的硬體驗收。

最初已做獨立唯讀架構審查，納入 eMMC 備份、軟體防寫限制、配套 overlay、不可用 `switch_root` 冒充核心切換，以及開機鏈橋接的驗證界線。文件與狀態檢查僅屬計畫品質檢查，不記入實板測試數；後續實板證據另記，不能被此初始規劃說明覆蓋。

## 8. 技術依據與界線

- [U-Boot MMC 命令](https://docs.u-boot.org/en/latest/usage/cmd/mmc.html)：具備選擇媒體及讀取功能，但命令與驅動需在實際版本啟用；不代表現有 SPL 自動支援 eMMC，也不授權使用不可逆設定命令。
- [U-Boot 核心啟動命令](https://docs.u-boot.org/en/latest/usage/cmd/booti.html)：可傳入核心、initrd 與 DTB；本計畫推論可用來建立系統層測試路徑，仍需核對實際建置選項、位址及板上交接。
- [Linux 初始 RAM 系統說明](https://docs.kernel.org/admin-guide/initrd.html)：支援初始 RAM 系統與後續根系統交接；救援用途的驅動、容量、網路與實板可靠性須另驗。

上述文件支援軟體設計方向，不構成這片板子或十套映像已測通的證據。
